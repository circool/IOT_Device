# Универсальное устройство умного дома

Универсальное устройство на базе ESP8266 или ESP32, способное выполнять функции

- вентилятор управляемый датчиком температуры/влажности
- датчик состояния окружающей среды
- управляемый выключатель 

## Возможности

### Основные

Устройство в зависимости от типа поддерживает следующие возможности

 - мониторинг показаний датчика
 - управление исполнительным устройством в ручном и автоматическим режимах
 - индикация состояния на web странице
 - интеграция в системы IoT по протоколу WiFi/MQTT

### Вспомогательные

Для работы используются следующие функциональные возможности

 - Поддержка "Тихого" режима для вентилятора (ШИМ)
 - Таймер отложенного включения
 - Принудительное выключение исполнительного механизма при старте
 - Прямое управление исполнительным механизмом через веб-интерфейс или MQTT
 - Веб‑интерфейс, точка доступа для настройки
 - Обновление прошивки по воздуху (OTA).
 - Хранение настроек в энергонезависимой памяти (EEPROM)

## Пояснения и термины

**Тихий режим**  – режим тихого вращения: питание на мотор подаётся импульсами (ШИМ) с эмпирически подобранной скважностью. Вентилятор крутится не на полной скорости, шумит значительно меньше. При этом для снижения стресса исполнительного устройства стартовый импульс обеспечивает раскрутку мотора а последуюшие импульны только поддерживают вражение.
Первый импульс всегда имеет длительность `PWM_STARTING`, последующие импульсы подчиняются установленным значениям `SLOW_MODE_DUTY_CYCLE`

**Выключение при старте** - принудительное выключение исполнительного устройства при включении питания. Гарантирует что после включении устройства, его исполнительный механизм будет установлен в выключенное положение.

- `true` — после включения питания принудительно выключает вентилятор
- `false` — сохраняет состояние пина (как до отключения питания)
- Параметр сохраняется в EEPROM и настраивается через веб-интерфейс

**Таймер отложенного включения** - параметр `delaySeconds` содержит величину задержки в секундах, по истечении которой исполнительный механизм включается независимо от показаний датчиков. Может быть отключен установкой нулевой величины.

**Ограничиение времени работы** - параметр `maxOnTime` ограничивает максимальное время непрерывной работы исполнительного механизма для обеспечения безопасности. Может быть отключен установкой нулевой величины.


## 1. Основные возможности

- Чтение конфигурации из EEPROM при старте (с контролем целостности CRC16).
- Автономный режим по датчикам (температура/влажность) и/или по таймеру.
- Ручной режим через MQTT‑команды (наивысший приоритет).
- Публикация состояния вентилятора, датчиков и конфигурации в MQTT только при изменениях.
- Приём команд изменения конфигурации по MQTT с сохранением в EEPROM.
- Веб‑сервер с мониторингом и страницей OTA.
- Режим точки доступа (AP) для первоначальной настройки или при отсутствии WiFi.
- Captive Portal – автоматическое перенаправление на страницу настройки.
- Кнопка сброса настроек к заводским (GPIO0).


## 2. Описание устройства

Прошивка поддерживает три типа устройств (`DEVICE_TYPE` в `config.h`):

| DEVICE_TYPE | Назначение                    | Компоненты                              |
|-------------|-------------------------------|-----------------------------------------|
| 1           | Вентилятор с датчиками        | Датчик + управление вентилятором        |
| 2           | Только датчик                 | Только сенсор (без реле/ШИМ)            |
| 3           | Управляемый выключатель       | Только управление (без датчика)         |



### 2.1 Компоненты устройства

Устройство может работать в нескольких конфигурациях, определяемых наличием тех или иных его составляющих. Максимальный набор выглядит так:

| Компонент                     | Примечание                                                                 |
|-------------------------------|----------------------------------------------------------------------------|
| Плата                         | ESP8266 (NodeMCU, ESP‑01 с адаптером) или ESP32                            |
| Исполнительный механизм       | **Твердотельное реле G3MB‑202P** (5V, Low Level Trigger) – допускает ШИМ   |
| Датчик температуры/влажности  | AHT10 (I2C) **или** DHT11/DHT22 (однопроводной GPIO)                       |
| Питание                       | 5V DC (общее для ESP и реле). Если мотор 12В – отдельное питание через реле|
| Кнопка сброса                 | GPIO0 (подтяжка к GND)                                                     |

### Поддерживаются следующие типы датчиков

| SENSOR_TYPE | Датчик       | Интерфейс |
|-------------|--------------|-----------|
| 1           | AHT10        | I2C       |
| 2           | DHT11/DHT22  | 1-Wire    |

**Важно:** Для правильной работы режима Slow‑Mode обязательно использовать **твердотельное реле** (SSR).

### Назначение пинов

| Назначение                    | ESP8266 | ESP32  |
|-------------------------------|---------|--------|
| Управление вентилятором (PWM) | GPIO14  | GPIO4  |
| AHT10 SDA                     | GPIO4   | GPIO21 |
| AHT10 SCL                     | GPIO5   | GPIO22 |
| DHT11/22 (SENSOR_PIN)         | GPIO2   | GPIO2  |
| Кнопка сброса (RESET_PIN)     | GPIO0   | GPIO0  |

## 3. Конфигурация устройства

### 3.1. Типы устройств и условная компиляция

**Структура `Config` и набор констант зависят от `DEVICE_TYPE`** — ненужные поля исключаются из компиляции для экономии памяти.

### 3.2. Константы прошивки (`config.h`)

```cpp
// Тип устройства
#define DEVICE_TYPE 1

// Датчик (только для DEVICE_TYPE 1 или 2)
#define SENSOR_TYPE 1                // 1 – AHT10, 2 – DHT11/22
#define SENSOR_PIN 2                 // пин для DHT (если SENSOR_TYPE == 2)
#define DHT_TYPE DHT11               // DHT11, DHT22 или DHT21

// Управление (только для DEVICE_TYPE 1 или 3)
#define SWITCH_PIN 14                // пин управления реле
#define PWM_FREQUENCY 5             // частота ШИМ для Slow‑Mode, Гц
#define PWM_RESOLUTION 8             // разрешение ШИМ (0..255)
#define SLOW_MODE_DUTY_CYCLE 128     // скважность Slow‑Mode по умолчанию

// Поведение
#define SENSOR_DURATION 10           // интервал опроса датчика, сек
#define MAX_ON_TIME_SEC 3600         // аварийное отключение, сек

// Пороги по умолчанию (DEVICE_TYPE 1)
#define DEFAULT_LOW_TEMP 27.0
#define DEFAULT_HIGH_TEMP 29.0
#define DEFAULT_LOW_HUM 60.0
#define DEFAULT_HIGH_HUM 70.0
#define DEFAULT_AUTOMATIC_MODE true

// Управление по умолчанию (DEVICE_TYPE 1 или 3)
#define DEFAULT_DELAY_SECONDS 60
#define DEFAULT_SLOW_MODE false
#define DEFAULT_FORCE_OFF_ON_BOOT true  // принудительно выключать при старте

// Сеть
#define AP_IP_ADDRESS "192.168.4.1"

// MQTT
#define STATE_PUBLISH_INTERVAL_MS 3000
#define MQTT_KEEPALIVE_SEC 2
#define MQTT_RECONNECT_DELAY_MS 5000
#define WIFI_CHECK_INTERVAL_MS 10000
#define AP_FALLBACK_TIMEOUT_MS 120000
```

### 3.3. Файл `credentials.h` (опционально)

Используется **только при невалидной EEPROM** как источник начальных WiFi/MQTT параметров.

```cpp
#define SSID_NAME "MyWiFi"
#define WIFI_PASSWORD "password"
#define MQTT_ADDRESS "192.168.1.100"
#define MQTT_PORT 1883
#define MQTT_USER "user"
#define MQTT_PASSWORD "mqtt_password"
```

**Логика:**
- EEPROM невалиден → `config_setDefaults()` устанавливает hardware + загружает credentials → AP mode
- EEPROM валиден → credentials не используются
- Нет `credentials.h` → пустые значения по умолчанию

### 3.4. Slow‑Mode




- `slowModeEnabled == false` → `HIGH` (100% мощности)
- `slowModeEnabled == true` → ШИМ: частота `PWM_FREQUENCY` (5 Гц), скважность `slowModeDuty` (0–255)
- Переключается через MQTT (`c/fan/slowMode`) или веб-интерфейс, сохраняется в EEPROM

### 3.5. Поддержка датчиков

При ошибке чтения датчик считается отсутствующим — управление переключается на таймер.

### 3.6. Параметры EEPROM (структура `Config`)

```cpp
struct ScheduleEntry {         // Только DEVICE_TYPE 1 или 3
  uint8_t hour;
  uint8_t minute;
  bool state;
};

struct Config {
  // Общие поля:
  uint16_t magic;              // 0x5A6B
  uint16_t crc;                // CRC16 всей структуры
  char wifiSsid[32];
  char wifiPassword[64];
  char mqttBroker[64];
  uint16_t mqttPort;
  char mqttUser[32];
  char mqttPassword[64];
  char mqttClientId[24];       // генерируется из MAC если пусто
  
  // DEVICE_TYPE 1:
  double lowHum, highHum;
  double lowTemp, highTemp;
  bool automaticMode;
  
  // DEVICE_TYPE 1 или 3:
  int delaySeconds;
  bool slowModeEnabled;
  uint16_t slowModeDuty;
  uint32_t maxOnTime;
  bool forceOffOnBoot;         // true = принудительно выключать при старте
  uint8_t scheduleCount;
  ScheduleEntry schedule[10];  // резерв
  
  // DEVICE_TYPE 1 или 2:
  uint16_t sensorInterval;     // 2-300 сек
  
  uint8_t reserved[31];        // всегда 0 для стабильности CRC
};
```

**Методы:**
- `config_init()` — инициализация EEPROM
- `config_read()` — чтение с проверкой CRC
- `config_write()` — запись с пересчётом CRC
- `config_setDefaults()` — сброс на значения по умолчанию (hardware + credentials)
- `config_clear()` — сброс + сохранение в EEPROM

## 4. Логика работы

### 4.1. Инициализация

**Вар. 1 — EEPROM невалиден:**
1. `config_setDefaults()` — hardware значения из констант + WiFi/MQTT из `credentials.h`
2. Поднимается точка доступа для настройки

**Вар. 2 — EEPROM валиден:**
1. Конфигурация загружается из EEPROM
2. Подключение к WiFi/MQTT с сохранёнными параметрами
3. При неудаче — переход к Вар. 1 через `AP_FALLBACK_TIMEOUT_MS`

### 4.2. Режимы

| Режим | Активация | Поведение |
|-------|-----------|-----------|
| **Автономный** | `manualOverride == false` | Управление по датчикам и/или таймеру |
| **Ручной** | MQTT `ON`/`OFF` → `fan_setOverrideMode(true)` | Только по MQTT-командам |
| **Возврат в авто** | MQTT `AUTO`/`1` → `fan_setOverrideMode(false)` | Сброс ручного режима |

### 4.3. Автономное управление

Подрежимы работают независимо: включение по **ИЛИ**, выключение по **И**.

#### 4.3.1. По датчикам

**Включение** (хотя бы одно):
- `currentTemp >= highTemp`
- `currentHum >= highHum`

**Выключение** (оба):
- `currentTemp <= lowTemp`
- `currentHum <= lowHum`

#### 4.3.2. По таймеру

При `delaySeconds > 0`:
- Вентилятор выключен и таймер не активен → запуск таймера на `delaySeconds`
- Таймер истекает → включение вентилятора до отсечки `maxOnTime`
- После `maxOnTime` → принудительное выключение, таймер перезапускается

#### 4.3.3. Начальное состояние (`forceOffOnBoot`)

- `true` — после включения питания принудительно выключает вентилятор
- `false` — сохраняет состояние пина (как до отключения питания)
- Параметр сохраняется в EEPROM и настраивается через веб-интерфейс

### 4.4. Slow‑Mode

```cpp
if (fanOn) {
    if (slowModeEnabled) {
        analogWrite(SWITCH_PIN, slowModeDuty);
    } else {
        digitalWrite(SWITCH_PIN, HIGH);
    }
} else {
    digitalWrite(SWITCH_PIN, LOW);
}
```

### 4.5. Защита `maxOnTime`

- При каждом включении запускается таймер
- При превышении — принудительное выключение
- В MQTT публикуется `error = "max_on_time"`

## 5. MQTT протокол

### 5.1. Общие топики

Базовый префикс — `mqttClientId` (например, `fan_C0:49:EF:6B:D8:4C`).

| Назначение | Топик |
|-----------|-------|
| Статус (LWT) | `{ID}/status` |
| Сброс настроек | `{ID}/c/system/reset` |

### 5.2. DEVICE_TYPE 1 (вентилятор с датчиками)

**State-топики:**

| Назначение | Топик |
|-----------|-------|
| Состояние вентилятора | `{ID}/fan/state` |
| Авто режим | `{ID}/fan/autoMode` |
| Slow‑Mode | `{ID}/fan/slowMode` |
| Скважность | `{ID}/fan/slowModeDuty` |
| Задержка | `{ID}/fan/delaySec` |
| Температура | `{ID}/sensor/temperature` |
| Влажность | `{ID}/sensor/humidity` |
| Пороги темп. | `{ID}/sensor/lowTemp`, `/highTemp` |
| Пороги влаж. | `{ID}/sensor/lowHum`, `/highHum` |
| Ошибки | `{ID}/error` |

**Command-топики:**

| Команда | Топик | Payload |
|---------|-------|---------|
| Управление вентилятором | `{ID}/c/fan/state` | `ON`/`OFF`/`1`/`0` |
| Режим (авто/ручной) | `{ID}/c/fan/autoMode` | `AUTO`/`1`/`0` |
| Slow‑Mode | `{ID}/c/fan/slowMode` | `1`/`0`/`ON`/`OFF` |
| Скважность | `{ID}/c/fan/slowModeDuty` | 0–255 |
| Пороги темп. | `{ID}/c/sensor/lowTemp`, `/highTemp` | -40.0...+85.0 |
| Пороги влаж. | `{ID}/c/sensor/lowHum`, `/highHum` | 0–100 |
| Задержка | `{ID}/c/fan/delaySec` | 0–3600 |

### 5.3. DEVICE_TYPE 2 (только датчик)

**State-топики:**

| Назначение | Топик |
|-----------|-------|
| Температура | `{ID}/sensor/temperature` |
| Влажность | `{ID}/sensor/humidity` |

Command-топиков нет.

### 5.4. DEVICE_TYPE 3 (управляемый выключатель)

**State-топики:**

| Назначение | Топик |
|-----------|-------|
| Состояние | `{ID}/switch/state` |

**Command-топики:**

| Команда | Топик | Payload |
|---------|-------|---------|
| Управление | `{ID}/c/switch/state` | `ON`/`OFF`/`1`/`0` |

### 5.5. Типы command-топиков

#### Оперативные (без сохранения в EEPROM)

| Топик | Payload | Действие |
|-------|---------|----------|
| `c/fan/state` | `ON`/`OFF`/`1`/`0` | Включение/выключение + ручной режим |
| `c/switch/state` | `ON`/`OFF`/`1`/`0` | Включение/выключение + ручной режим |
| `c/fan/autoMode` | `AUTO`/`1` | Автоматический режим |
| `c/fan/autoMode` | `0` | Ручной режим без изменения состояния |
| `c/system/reset` | `1` | Сброс к заводским + перезагрузка |

#### Конфигурационные (с сохранением в EEPROM)

| Топик | Payload | Диапазон | Применение |
|-------|---------|----------|------------|
| `c/fan/slowMode` | `1`/`0`/`ON`/`OFF` | — | Немедленно |
| `c/fan/slowModeDuty` | число | 0–255 | Немедленно, если slow mode активен |
| `c/sensor/lowTemp` | число | -40.0...+85.0 | Немедленно |
| `c/sensor/highTemp` | число | -40.0...+85.0 | Немедленно |
| `c/sensor/lowHum` | число | 0–100 | Немедленно |
| `c/sensor/highHum` | число | 0–100 | Немедленно |
| `c/fan/delaySec` | целое | 0–3600 | Таймер пересчитывается с учётом прошедшего времени |

### 5.6. Логика публикации

- `fan/state` — при изменении состояния вентилятора
- `sensor/temperature`, `sensor/humidity` — при изменении значений
- Конфигурационные топики — однократно при подключении и при изменении через MQTT/веб
- `status` (`Online`) — каждые `MQTT_KEEPALIVE_SEC` (2 сек)
- LWT `Offline` — через `keepalive × 1.5` (3 сек) после отключения

### 5.7. QoS

- Все state-топики: **QoS 1**
- `status`: **retain = true**
- Подписки: **QoS 1**

## 6. Веб‑интерфейс

### 6.1. AP режим

Включается при:
- Невалидной EEPROM при старте
- Отсутствии WiFi более `AP_FALLBACK_TIMEOUT_MS` (120 сек)

Параметры:
- SSID: `SmartFan_XXXX` (последние 4 символа MAC)
- IP: `192.168.4.1`
- Captive Portal

**Страница конфигурации** (`http://192.168.4.1/`) позволяет настроить:
- WiFi SSID и пароль
- MQTT брокер, порт, логин, пароль, Client ID
- Пороги температуры и влажности
- Задержку включения (`delaySeconds`)
- Slow Mode (вкл/выкл, скважность)
- Автоматический режим
- Принудительное выключение при старте (`forceOffOnBoot`)
- Интервал опроса датчика (`sensorInterval`)
- Максимальное время непрерывной работы (`maxOnTime`)

### 6.2. Рабочий веб‑сервер

Страница статуса (`/`):
- Идентификатор устройства
- Температура/влажность с цветовой индикацией
- Состояние вентилятора (реальное с пина)
- Slow Mode статус
- Текущие пороги и задержка
- Обновление каждые `sensorInterval / 2` сек

### 6.3. OTA

- ESP32: `ElegantOTA`
- ESP8266: `AsyncElegantOTA`
- Страница: `/update`

## 7. EEPROM и надёжность

- Контроль целостности: `magic` + `CRC16`
- Несовпадение → AP режим с загрузкой credentials
- Сброс к заводским: MQTT `c/system/reset` или кнопка GPIO0 при старте
- Ошибка датчика → переключение на таймер (если `delaySeconds > 0`)
