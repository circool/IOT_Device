## **PROJECT.md** (актуальная версия)

```markdown
# Умное устройство: вентилятор с поддержкой Slow‑Mode и датчиков AHT10 / DHT11/22

Универсальное устройство на базе ESP8266 или ESP32, управляющее вентилятором (исполнительный механизм – твердотельное реле) на основании:

- показаний датчика температуры/влажности (AHT10 или DHT11/22);
- таймера (задержка включения);
- MQTT‑команд;
- веб‑интерфейса (точка доступа для настройки, OTA).

**Особенность:** Slow‑Mode – режим тихого вращения: питание на мотор подаётся импульсами (ШИМ) с эмпирически подобранной скважностью. Вентилятор крутится не на полной скорости, шумит значительно меньше.

---

## 1. Основные возможности

- Чтение конфигурации из EEPROM при старте (с контролем целостности CRC16).
- Автономный режим по датчикам (температура/влажность) или по таймеру.
- Управляемый режим – MQTT‑команды имеют наивысший приоритет.
- Автоматическое переключение между режимами при потере/восстановлении связи с брокером.
- Публикация телеметрии (температура, влажность, состояние вентилятора, текущие пороги) в MQTT.
- Приём команд изменения конфигурации (пороги, задержка, slow‑mode, автоматический режим) по MQTT.
- Веб‑сервер с информацией об устройстве и страницей OTA (обновление прошивки по воздуху).
- Режим точки доступа (AP) для первоначальной настройки или при длительном отсутствии WiFi.
- Captive Portal – автоматическое перенаправление на страницу настройки.
- Кнопка сброса настроек к заводским (GPIO0).

---

## 2. Состав устройства

| Компонент                     | Примечание                                                                 |
|-------------------------------|----------------------------------------------------------------------------|
| Плата                         | ESP8266 (NodeMCU, ESP‑01 с адаптером) или ESP32                            |
| Исполнительный механизм       | **Твердотельное реле G3MB‑202P** (5V, Low Level Trigger) – допускает ШИМ   |
| Датчик температуры/влажности  | AHT10 (I2C) **или** DHT11/DHT22 (однопроводной GPIO)                       |
| Питание                       | 5V DC (общее для ESP и реле). Если мотор 12В – отдельное питание через реле|
| Кнопка сброса                 | GPIO0 (подтяжка к GND)                                                     |

**Важно:** Для Slow‑Mode обязательно использовать **твердотельное реле** (SSR) – обычное электромагнитное быстро выйдет из строя. G3MB‑202P подходит, частота ШИМ – до 10 Гц.

### Назначение пинов (для обеих платформ)

| Назначение                    | ESP8266 | ESP32  |
|-------------------------------|---------|--------|
| Управление вентилятором (PWM) | GPIO14  | GPIO14 |
| AHT10 SDA                     | GPIO4   | GPIO21 |
| AHT10 SCL                     | GPIO5   | GPIO22 |
| DHT11/22 (SENSOR_PIN)         | GPIO2   | GPIO2  |
| Кнопка сброса (RESET_PIN)     | GPIO0   | GPIO0  |

> Пин для DHT задаётся константой `SENSOR_PIN`. Для AHT10 используются I2C‑пины по умолчанию.

## 3. Конфигурация устройства

Все параметры делятся на **константы прошивки** (задаются в `config.h`) и **параметры EEPROM** (изменяемые через MQTT/веб).

### 3.1. Константы прошивки (файл `config.h`)

```cpp
// ======================== НАСТРОЙКИ УСТРОЙСТВА ========================
#define DEVICE_TYPE 1                // 1 – вентилятор с датчиками
#define SENSOR_TYPE 1                // 1 – AHT10, 2 – DHT11/22
#define SENSOR_PIN 2                 // для DHT11/22
#define DHT_TYPE DHT11               // DHT11, DHT22 или DHT21
#define SWITCH_PIN 14                // пин управления реле
#define RESET_PIN 0                  // пин кнопки сброса

// ======================== НАСТРОЙКИ ШИМ ДЛЯ SLOW MODE ========================
#define PWM_FREQUENCY 10             // частота ШИМ для Slow‑Mode, Гц
#define PWM_RESOLUTION 8             // разрешение ШИМ (0..255)
#define SLOW_MODE_DUTY_CYCLE 128     // скважность Slow‑Mode (0..255)

// ======================== НАСТРОЙКИ ПОВЕДЕНИЯ ========================
#define SET_SWITCH_OFF               // при старте вентилятор выключен
#define SENSOR_DURATION 10           // интервал опроса датчика, секунд
#define MAX_ON_TIME_SEC 3600         // аварийное отключение при непрерывной работе

// ======================== НАСТРОЙКИ СЕТИ ========================
#define AP_IP_ADDRESS "192.168.4.1"  // IP адрес точки доступа

// ======================== ПОРОГИ ПО УМОЛЧАНИЮ ========================
#define DEFAULT_LOW_TEMP 27.0
#define DEFAULT_HIGH_TEMP 29.0
#define DEFAULT_LOW_HUM 60.0
#define DEFAULT_HIGH_HUM 70.0
#define DEFAULT_DELAY_SECONDS 60     // задержка ВКЛЮЧЕНИЯ (сек)
#define DEFAULT_AUTOMATIC_MODE true
#define DEFAULT_SLOW_MODE false

// ======================== НАСТРОЙКИ MQTT ========================
#define STATE_PUBLISH_INTERVAL_MS 3000   // публикация состояния каждые 3 сек
#define MQTT_KEEPALIVE_SEC 4             // keepalive 4 секунды
#define MQTT_RECONNECT_DELAY_MS 5000
#define WIFI_CHECK_INTERVAL_MS 10000
#define AP_FALLBACK_TIMEOUT_MS 120000    // 2 минуты до AP режима

// ======================== ОТЛАДКА ========================
// #define DEBUG_ENABLE
// #define DEBUG_MQTT
// #define DEBUG_EEPROM
```

Все константы вынесены в `config.h` для централизованного управления.

### 3.2. Slow‑Mode (тихое вращение)

- При выключенном Slow‑Mode (`slowModeEnabled == false`) и включённом вентиляторе на `SWITCH_PIN` выставляется уровень `HIGH` (100% мощности).
- При включённом Slow‑Mode (`slowModeEnabled == true`) на `SWITCH_PIN` подаётся ШИМ‑сигнал:
  - частота = `PWM_FREQUENCY` (1–10 Гц, зависит от SSR)
  - скважность = `slowModeDuty` (0..255). Значение подбирается экспериментально.
- Slow‑Mode можно переключать по MQTT (команда `fan/c/slowMode`) или через веб‑интерфейс. Состояние сохраняется в EEPROM.

### 3.3. Поддержка датчиков

| `SENSOR_TYPE` | Датчик       | Интерфейс | Примечание                          |
|---------------|--------------|-----------|--------------------------------------|
| 1             | AHT10        | I2C       | Подключается к SDA/SCL, питание 3.3В |
| 2             | DHT11 / DHT22| 1-Wire    | Пин `SENSOR_PIN`, питание 5В или 3.3В|

Если датчик не отвечает или отсутствует, устройство переключается в режим управления по таймеру (если `delaySeconds > 0`).

### 3.4. Параметры, хранящиеся в EEPROM (структура `Config`)

```cpp
struct Config {
  uint16_t magic;           // 0x5A6B
  uint16_t crc;             // CRC16 всей структуры

  char wifiSsid[32];
  char wifiPassword[64];
  char mqttBroker[64];
  uint16_t mqttPort;
  char mqttUser[32];
  char mqttPassword[64];
  char mqttClientId[24];    // формируется из MAC, если пусто

  double lowHum, highHum;
  double lowTemp, highTemp;
  int delaySeconds;         // задержка ВКЛЮЧЕНИЯ (сек)
  bool automaticMode;       // автономное управление по датчикам
  bool slowModeEnabled;     // включён ли Slow‑Mode
  uint16_t slowModeDuty;    // скважность Slow‑Mode (0..255)

  uint16_t sensorInterval;  // интервал опроса датчика (сек)
  uint16_t maxOnTime;       // максимальное время непрерывной работы (сек)

  uint8_t scheduleCount;    // (резерв, не используется)
  struct ScheduleEntry {
    uint8_t hour;
    uint8_t minute;
    bool state;
  } schedule[10];

  uint8_t reserved[32];
};
```

Размер структуры ~200 байт, что помещается в EEPROM любого ESP.

**Методы работы с конфигурацией:**
- `config_read()` – чтение из EEPROM с проверкой CRC
- `config_write()` – запись в EEPROM с пересчётом CRC
- `config_setDefaults()` – установка значений по умолчанию
- `config_clear()` – сброс к заводским настройкам

Если при старте конфигурация невалидна (или EEPROM пуста), устройство переходит в **режим точки доступа** для настройки.

## 4. Логика работы

### 4.1. Режимы и их приоритет

| Режим                     | Активация                                                                 | Поведение                                                                 |
|---------------------------|---------------------------------------------------------------------------|---------------------------------------------------------------------------|
| **Автономный (датчик)**    | `automaticMode == true`, `manualOverride == false`, датчик исправен       | Управление по порогам температуры/влажности                              |
| **Автономный (таймер)**    | `automaticMode == true`, датчик неисправен, `delaySeconds > 0`            | Включение через `delaySeconds` секунд после старта или выключения        |
| **Управляемый**            | MQTT‑команда `switch/c` с `ON`/`OFF` → `manualOverride = true`           | Вентилятор только по MQTT-командам                                        |
| **Возврат в авто**         | Команда `fan/c/autoMode` = `AUTO` или `1`                                 | Сброс `manualOverride`, переход к автономной логике                       |

При потере MQTT-соединения более чем на 30 секунд `manualOverride` автоматически сбрасывается.

### 4.2. Автономное управление по датчикам

**Включение вентилятора**, если **хотя бы одно** из условий истинно:
- `currentTemperature >= highTemp`
- `currentHumidity >= highHum`

**Выключение вентилятора**, если **оба** условия истинны:
- `currentTemperature <= lowTemp`
- `currentHumidity <= lowHum`

**Задержка включения (`delaySeconds`):**
- При запуске устройства (если вентилятор выключен) запускается таймер на `delaySeconds` секунд.
- Если условия не превышают пороги, по истечении таймера вентилятор **ВКЛЮЧАЕТСЯ**.
- Если условия превысили пороги – включение происходит **НЕМЕДЛЕННО**, таймер сбрасывается.
- При выключении вентилятора (по условиям или команде) таймер запускается заново.
- Если `delaySeconds == 0` – таймер не запускается, вентилятор не включается автоматически.

**Начальное состояние (`SET_SWITCH_OFF`):**
- Когда константа определена – после включения питания вентилятор принудительно выключается.
- Когда константа не определена – вентилятор сохраняет состояние до перезагрузки.

**Slow‑Mode** активен, если `slowModeEnabled == true`. Не влияет на логику включения/выключения – только на мощность.

### 4.3. Slow‑Mode: действие при включении вентилятора

```cpp
if (fanShouldBeOn) {
    if (slowModeEnabled) {
        analogWrite(SWITCH_PIN, slowModeDuty);   // ШИМ‑сигнал
    } else {
        digitalWrite(SWITCH_PIN, HIGH);          // полная мощность
    }
} else {
    digitalWrite(SWITCH_PIN, LOW);               // выключено
}
```

Скважность `slowModeDuty` можно менять через MQTT (топик `c/fan/slowModeDuty`) или через веб‑интерфейс.

### 4.4. Управление по таймеру (при отсутствии датчика)

Если датчик не отвечает или отсутствует:
- При `delaySeconds > 0` – вентилятор включается через `delaySeconds` секунд после старта
- При `delaySeconds == 0` – вентилятор всегда выключен

### 4.5. Защита `maxOnTime`

- Таймер непрерывной работы вентилятора запускается при каждом включении.
- Если время работы превышает `maxOnTime` (по умолчанию 3600 секунд), вентилятор принудительно выключается.
- В MQTT публикуется сообщение: `MQTT_CLIENT_ID/error` = `"max_on_time"`.

## 5. MQTT протокол

### 5.1. Формирование топиков

Базовый префикс – **значение `mqttClientId` из конфигурации** (например, `fan_C0:49:EF:6B:D8:4C`). Разделитель – `/`. Для команд используется дополнительный уровень `c/`.

**Топики публикации (state):**

| Назначение                     | Топик                                                     |
|--------------------------------|-----------------------------------------------------------|
| Статус (LWT)                   | `{CLIENT_ID}/status`                                      |
| Состояние вентилятора          | `{CLIENT_ID}/switch/state`                                |
| Slow‑Mode статус               | `{CLIENT_ID}/fan/slowMode`                                |
| Скважность Slow‑Mode           | `{CLIENT_ID}/fan/slowModeDuty`                            |
| Температура                    | `{CLIENT_ID}/sensor/temperature`                          |
| Влажность                      | `{CLIENT_ID}/sensor/humidity`                             |
| Нижняя граница температуры     | `{CLIENT_ID}/sensor/lowTemp`                              |
| Верхняя граница температуры    | `{CLIENT_ID}/sensor/highTemp`                             |
| Нижняя граница влажности       | `{CLIENT_ID}/sensor/lowHum`                               |
| Верхняя граница влажности      | `{CLIENT_ID}/sensor/highHum`                              |
| Задержка включения             | `{CLIENT_ID}/fan/delaySec`                                |
| Автоматический режим           | `{CLIENT_ID}/fan/autoMode`                                |
| Ошибки                         | `{CLIENT_ID}/error`                                       |

**Топики подписки (command):**

| Команда                        | Топик                                  | Payload                        |
|--------------------------------|----------------------------------------|--------------------------------|
| Управление вентилятором        | `{CLIENT_ID}/c/switch/state`           | `ON` / `OFF`                   |
| Включить/выключить Slow‑Mode   | `{CLIENT_ID}/c/fan/slowMode`           | `1` / `0`                      |
| Установить скважность Slow‑Mode| `{CLIENT_ID}/c/fan/slowModeDuty`       | число 0–255                    |
| Изменить нижнюю границу темп.  | `{CLIENT_ID}/c/sensor/lowTemp`         | число (например `18.5`)        |
| Изменить верхнюю границу темп. | `{CLIENT_ID}/c/sensor/highTemp`        | число                           |
| Изменить нижнюю границу влажн. | `{CLIENT_ID}/c/sensor/lowHum`          | число                           |
| Изменить верхнюю границу влажн. | `{CLIENT_ID}/c/sensor/highHum`        | число                           |
| Изменить задержку включения    | `{CLIENT_ID}/c/fan/delaySec`           | целое (секунды)                |
| Вернуться в автономный режим   | `{CLIENT_ID}/c/fan/autoMode`           | `AUTO` или `1`                 |
| Сброс к заводским настройкам   | `{CLIENT_ID}/c/system/reset`           | `1`                            |

### 5.2. Форматы и QoS

- Все state-топики публикуются с **QoS 1**, `retain = false` (кроме `status` – `retain = true` для LWT).
- Подписка на command-топики – **QoS 1**.
- Числовые значения – десятичная точка (например, `25.5`). Логические – `0`/`1` или `ON`/`OFF`/`AUTO`.

### 5.3. Обнаружение потери связи

- Устройство публикует состояние вентилятора каждые 3 секунды (`STATE_PUBLISH_INTERVAL_MS`).
- Keepalive = 4 секунды (`MQTT_KEEPALIVE_SEC`).
- При отключении питания брокер обнаруживает разрыв через 4-6 секунд и публикует LWT `Offline`.

## 6. Веб‑интерфейс и конфигурация

### 6.1. Режим инициализации (AP)

Включается, если:
- При старте конфигурация EEPROM невалидна.
- WiFi не может подключиться к сохранённой сети более 120 секунд.

Параметры точки доступа:
- SSID: `SmartFan_XXXXXX` (XXXXXX – последние 6 символов MAC).
- IP: `192.168.4.1` (задаётся константой `AP_IP_ADDRESS`).
- **Captive Portal:** все HTTP запросы перенаправляются на страницу конфигурации.

**Страница конфигурации** (`http://192.168.4.1/`) позволяет настроить:
- WiFi SSID и пароль
- MQTT брокер, порт, логин, пароль, Client ID
- Пороги температуры и влажности
- Задержку включения (`delaySeconds`)
- Slow Mode (вкл/выкл, скважность)
- Автоматический режим
- Интервал опроса датчика (`sensorInterval`)
- Максимальное время непрерывной работы (`maxOnTime`)

После сохранения устройство перезагружается с новыми настройками.

### 6.2. Рабочий веб‑сервер

По адресу `http://<IP_устройства>/` отображается:
- Идентификатор устройства (`mqttClientId`) в заголовке
- Текущие показания датчика (цветовая индикация: синий – норма, красный – превышение, зелёный – понижение)
- Состояние вентилятора (красный – ВКЛ, синий – ВЫКЛ)
- Slow Mode статус и скважность
- Текущие пороги и задержка
- Ссылка на страницу OTA (`/update`) и расширенные настройки (`/config`)

Страница автоматически обновляется каждые `sensorInterval / 2` секунд.

### 6.3. OTA (обновление по воздуху)

- Для ESP32 используется `ElegantOTA`, для ESP8266 – `AsyncElegantOTA`.
- Страница OTA доступна по адресу `/update`.
- Позволяет загрузить новую прошивку (bin‑файл) без перепрошивки через USB.

## 7. EEPROM и надёжность

- **Контроль целостности:** `magic` + `CRC16`. При несовпадении – переход в AP режим.
- **Сброс к заводским:** MQTT‑команда `c/system/reset` или удержание кнопки на GPIO0 при включении.
- **Watchdog:** аппаратный сторожевой таймер (сброс в `loop()`).
- **Обработка ошибок датчика:** при ошибке чтения датчик считается отсутствующим – управление переключается на таймер (если `delaySeconds > 0`).
- **Отказ реле:** не обрабатывается программно. Рекомендуется внешний предохранитель.

### 12.2. Размер прошивки для данного проекта

| Компонент | Размер (приблизительно) |
|-----------|------------------------|
| Базовая прошивка | 400-450 KB |
| С отладкой (DEBUG_ENABLE) | 450-500 KB |
| С OTA (дополнительный раздел) | +400-450 KB |
| **Итого с OTA** | **~850-950 KB** |

### 12.3. Рекомендации по выбору

**Для работы с OTA (рекомендуется):**
- Минимум 2 MB flash (ESP-01S)
- Оптимально 4 MB flash (ESP-12F, ESP-12E, NodeMCU, Wemos D1 Mini)
- **Лучший выбор:** NodeMCU v3 или Wemos D1 Mini (4 MB)

**Для работы без OTA (только через USB):**
- Минимум 1 MB flash (ESP-01)
- Подходит ESP-01 с отключённой отладкой

### 12.4. Использование памяти на ESP-12F (NodeMCU)

| Память | Использовано | Доступно | Процент |
|--------|--------------|----------|---------|
| **Flash (программа)** | ~615 KB | 4 MB | 58.9% |
| **Flash (OTA раздел)** | 0 KB | ~1 MB | 0% |
| **RAM** | ~55 KB | 80 KB | 66.9% |

### 12.5. Проверка вашего модуля

Чтобы узнать, сколько flash у вашего модуля:

1. **Посмотрите на маркировку чипа памяти:**
   - `25Q80` = 1 MB (8 Mbit)
   - `25Q16` = 2 MB (16 Mbit)
   - `25Q32` = 4 MB (32 Mbit)
   - `25Q64` = 8 MB (64 Mbit)

2. **Используйте скетч для определения:**
```cpp
#include <ESP8266WiFi.h>
void setup() {
  Serial.begin(115200);
  Serial.printf("Flash size: %d bytes\n", ESP.getFlashChipSize());
  Serial.printf("Real flash size: %d bytes\n", ESP.getFlashChipRealSize());
}
void loop() {}

```
