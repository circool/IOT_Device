# Универсальное устройство умного дома

## Описание проекта

### Цель создания

Устройство разработано для автоматического управления вытяжной вентиляцией в туалете и ванной комнате. В типовой квартирной разводке вытяжной вентилятор подключён к цепи освещения и включается одновременно со светом, работая всё время пока в помещении горит свет — без учёта реальной потребности в вентиляции. Устройство решает эту проблему: вентилятор включается автоматически только при превышении порогов температуры или влажности, а не при каждом заходе в помещение. Поддерживается тихий режим работы (ШИМ с регулируемой скважностью 0-100%) и **адаптивный тихий режим**, который автоматически подстраивает мощность вентилятора для поддержания комфортного микроклимата. Также присутствует таймер безопасности, принудительно отключающий вентилятор после заданного времени. Питание организовано от той же цепи освещения: устройство работает только когда горит свет, и полностью обесточивается после выключения — это исключает холостой расход электроэнергии и продлевает ресурс оборудования. Интеграция в системы умного дома через WiFi/MQTT позволяет удалённо отслеживать показания датчиков, управлять вентилятором и менять настройки. Прошивка универсальна и поддерживает три конфигурации: вентилятор с датчиком, автономный датчик и управляемый выключатель.

### Конструкция и компоненты

Устройство собрано на базе микроконтроллера ESP32-WROOM-32 или ESP8266 (ESP-12F) — компактной платы с WiFi, достаточной для задач мониторинга и управления. Датчик температуры и влажности — AHT10 с интерфейсом I2C (точность ±0.3°C и ±2%) или DHT11/DHT22 с однопроводным интерфейсом; выбор определяется доступностью компонентов, прошивка поддерживает оба типа. Исполнительный механизм — твердотельное реле G3MB-202P в виде готового модуля (доступен на AliExpress), включающего плату с обвязкой и винтовыми клеммами: два контакта под нагрузку 220V и три контакта управления (VCC, GND, CH1). Реле с низкоуровневым управлением допускает ШИМ-регулировку для тихого режима и коммутирует ток до 2А при 220V. Питание 3.3V DC подаётся от миниатюрного модуля AC-DC преобразователя 220V → 3.3V, подключённого параллельно цепи освещения.

Устройство собрано из отдельных модулей, соединённых проводами: AC-DC преобразователь → ESP на несущей плате → модуль реле с винтовыми клеммами → датчик на выносном разъёме. В проекте также разработана принципиальная схема в KiCad для самостоятельного изготовления единой печатной платы.

Рекомендуется защита собранного устройства термоусадочной трубкой: в жилом помещении количество конденсата в вентиляционном канале редко достигает уровня, способного нарушить работу электроники, однако изоляция предотвращает случайное замыкание и продлевает срок службы. Кнопка сброса (GPIO0) используется при разработке и служит аварийным решением для возврата к заводским настройкам при непредвиденной потере доступа по сети — удержание более 3 секунд очищает конфигурацию.

### Монтаж и подключение

Устройство устанавливается в разрыве вентиляционного тракта: между вытяжным вентилятором и гофрорукавом, ведущим в общедомовую шахту. Такое расположение помещает датчик в поток воздуха из помещения, а электронику защищает от прямого контакта с пользователем. Питание 220V подаётся от клемм освещения параллельно лампе: фаза и ноль заводятся на вход AC-DC преобразователя. Силовая часть твердотельного реле включена последовательно с вентилятором в цепь 220V — таким образом, вместо прямого соединения «свет включился → вентилятор включился» образуется управляемый разрыв: свет включился → устройство получило питание → устройство принимает решение о включении вентилятора на основе показаний датчика. При выключении света питание снимается полностью, вентилятор гарантированно останавливается.

## Основные возможности

- Мониторинг показаний датчика и публикация в MQTT при изменениях
- Управление вентилятором в ручном режиме (через MQTT, наивысший приоритет) и режиме управления сенсором (по датчикам)
- Таймер отложенного включения и аварийного отключения
- Тихий режим (ШИМ) с настраиваемой скважностью 0-100%
- **Адаптивный тихий режим** — автоматическая регулировка мощности вентилятора для поддержания температуры и влажности на уровне, зафиксированном при включении
- Принудительное выключение при старте
- Хранение настроек в EEPROM с контролем целостности (CRC16)
- Веб-интерфейс для настройки и OTA-обновления прошивки
- Точка доступа (AP) для первоначальной настройки или при отсутствии WiFi
- Сброс к заводским настройкам кнопкой, через MQTT или веб (опционально)

## Поддерживаемые конфигурации устройства

Прошивка поддерживает три типа устройств (`DEVICE_TYPE` в `config.h`):

| DEVICE_TYPE | Назначение | Компоненты |
|-------------|-----------|------------|
| 1 | Вентилятор с датчиками | Датчик + управление вентилятором |
| 2 | Только датчик | Только сенсор (без реле/ШИМ) |
| 3 | Управляемый выключатель | Реле/ШИМ, без датчика. Ручное управление через MQTT/веб. Поддерживает таймер отложенного включения и аварийного отключения. `sensorControlMode` и `adaptiveMode` отсутствуют. |

## Логика работы

Предусмотрено два режима работы — режим настройки и обычный.

### Первый запуск

При включении устройство пытается прочитать конфигурацию из EEPROM:
- при успешном чтении параметров происходит переход к обычному режиму;
- при неправильных или отсутствующих параметрах происходит переход к режиму настройки.

### Режим настройки

При включении устройство выполняет следующие действия:

1. Использует значения по умолчанию из `credentials.h` для первоначальной инициализации параметров
2. Запускает режим точки доступа (AP) с SSID вида `{Fan|Sensor|Switch}_XXXX`
3. Запускает веб-сервер на `192.168.4.1` со страницей настройки
4. Пользователь изменяет (при необходимости) параметры WiFi и MQTT и сохраняет их
5. После сохранения устройство перезагружается и переходит в обычный режим

Перед сохранением введённых пользователем настроек производится их валидация. Неверные (отсутствующие) значения не допускаются. В режиме настройки управление исполнительным механизмом и опрос датчиков не производятся.

### Обычный режим

При включении устройство выполняет следующие действия:

1. Читает конфигурацию из EEPROM
2. Инициализирует датчик (если предусмотрен типом устройства)
3. Инициализирует пин управления исполнительным механизмом (если предусмотрен)
4. Начинает выполнять основную функцию, не дожидаясь соединения с WiFi/MQTT:
   - периодический опрос датчика (интервал `sensorInterval`)
   - управление исполнительным механизмом по следующему приоритету:
     - **Ручной режим** (через MQTT или веб) — наивысший приоритет
     - **Режим управления сенсором** — по показаниям датчиков (для DEVICE_TYPE 1)
     - **Таймер отложенного включения** — включение через `delaySeconds` после того, как вентилятор был выключен
   - контроль максимального времени непрерывной работы (`maxOnTime`)
   - обслуживание веб-сервера (страница состояния, страница настройки, OTA обновление)
   - при наличии соединения с MQTT:
     - публикация показаний датчиков при изменении
     - публикация состояния исполнительного механизма и конфигурации при изменении
5. Подключается к WiFi сети по сохранённым параметрам
6. При невозможности подключения в течение `AP_FALLBACK_TIMEOUT_MS` переходит в режим настройки
7. Подключается к MQTT брокеру и публикует статус `Online`
8. При потере соединения с MQTT — автоматическая попытка переподключения
9. При потере соединения с WiFi — попытка переподключения, затем переход в режим точки доступа

## Описание режимов и терминов

**Режим управления сенсором (для DEVICE_TYPE = 1):**
- Включение происходит при превышении хотя бы одного из верхних порогов: температура ≥ `highTemp` **или** влажность ≥ `highHum`
- Выключение происходит при одновременном снижении обоих показателей ниже нижних порогов: температура ≤ `lowTemp` **и** влажность ≤ `lowHum`

**Ручной режим:**

При получении прямой внешней команды (по MQTT или через веб-интерфейс), изменяющей состояние исполнительного механизма, устройство переходит в ручной режим. В ручном режиме показания датчика и таймер отложенного включения игнорируются — устройство реагирует только на прямые команды. Таймер аварийного отключения (maxOnTime) продолжает работать, показания датчика продолжают публиковаться. Возврат в режим управления сенсором возможен только по внешней команде (MQTT топик `sensorControlMode` или кнопка на веб-странице) либо после перезагрузки устройства.
Для DEVICE_TYPE 3 (управляемый выключатель) ручной режим — единственный режим работы. `sensorControlMode` отсутствует. Таймер отложенного включения работает всегда (когда вентилятор выключен).

**Таймер отложенного включения:**

Параметр `delaySeconds` содержит величину задержки в секундах. Таймер запускается каждый раз, когда вентилятор выключается:

в режиме управления датчиком — по его показаниям (DEVICE_TYPE 1)
принудительно при старте (`bootState`)
в ручном режиме (DEVICE_TYPE 3)
Если вентилятор остаётся выключенным дольше `delaySeconds`, таймер срабатывает — включает вентилятор.
Для DEVICE_TYPE 1 при срабатывании таймера устройство переходит в ручной режим.
Если датчик включает вентилятор до истечения таймера — таймер сбрасывается.
Может быть отключён установкой `delaySeconds = 0`.

**Примечание:** Управление в режиме управления сенсором и таймер отложенного включения — независимые процедуры, влияющие на состояние исполнительного механизма по логике **ИЛИ**: вентилятор включается, если датчик требует включения **или** таймер истёк.

**Выключение при старте** — принудительное выключение исполнительного устройства при включении питания. Гарантирует, что после подачи питания вентилятор будет установлен в выключенное положение.
- `true` — после включения питания принудительно выключает вентилятор
- `false` — сохраняет состояние пина (как до отключения питания)
- параметр сохраняется в EEPROM и настраивается через веб-интерфейс или MQTT

**Таймер аварийного отключения** — параметр `maxOnTime` ограничивает максимальное время непрерывной работы исполнительного механизма для обеспечения безопасности. При превышении лимита вентилятор принудительно выключается и устройство переходит в ручной режим. Может быть отключён установкой `maxOnTime = 0`. Оставшееся время до аварийного отключения отображается на странице состояния в веб-интерфейсе.

**Slow Mode (тихий режим):**
- Режим тихого вращения: питание на мотор подаётся импульсами (ШИМ) с регулируемой скважностью 0-100%. 
- Значение 0% — вентилятор выключен, 100% — полная мощность (тихий режим выключен). Промежуточные значения обеспечивают пропорционально меньшую скорость вращения и уровень шума.
- Значения ниже `MIN_PWM_DUTY_PERCENT` (10%) считаются нерабочими для большинства вентиляторов. При получении команды установки скважности в диапазоне 1-9% устройство воспринимает это как намерение выключить вентилятор — выполняет полное выключение со сбросом скважности до сохранённого в EEPROM значения и публикацией `state = OFF`.
- Для снижения нагрузки на исполнительное устройство стартовый импульс всегда длится `PWM_STARTING` мс на полной мощности (100%), после чего переключается на заданную скважность.
- Параметр `pwmDutyPercent` хранит текущую скважность (0-100). При выключении вентилятора значение восстанавливается из сохранённой конфигурации.

**Адаптивный тихий режим:**
- Работает только когда `pwmDutyPercent < 100` и включён флаг `adaptiveMode`.
- При включении вентилятора фиксируются базовые показания датчика (температура и влажность).
- В процессе работы, с частотой опроса датчика, анализируется изменение показаний:
  - Если температура или влажность выросли выше эпсилона (`ADAPTIVE_EPSILON_TEMP` = 0.5°C или `ADAPTIVE_EPSILON_HUM` = 2%) — скважность увеличивается динамически (шаг 10-50% в зависимости от величины отклонения)
  - Если оба показателя снизились ниже отрицательного эпсилона — скважность уменьшается (шаг 10-20%)
- Минимальная скважность при адаптации ограничена `MIN_PWM_DUTY_PERCENT` = 10%
- При ошибке датчика во время работы адаптация отключается, вентилятор переключается на полную мощность (100%)
- При выключении вентилятора скважность восстанавливается до сохранённого в EEPROM значения, сбрасывая пользовательские изменения.
- При ручном изменении скважности через MQTT адаптивный режим автоматически отключается (без сохранения в EEPROM)

**Сохранение и отображение настроек:**
- **Только веб-форма настроек** (`/config` + `/save`) сохраняет параметры в EEPROM. Хранится в `staticConfig.*`.
- **MQTT/WEB команды** изменяют оперативное состояние параметров,после перезагрузки устройства все настройки восстанавливаются из EEPROM
- Оперативное изменение параметров/состояний публикуется в MQTT/отображается на ваб-странице состояния. Хранится в `config.*`
- При публикации измененных настроек в MQTT выполняется обновление только измененных параметров

**Сброс настроек:**
- При удержании кнопки сброса более 3 секунд происходит очистка конфигурации — сброс в значения по умолчанию и переход к режиму настройки
- Аналогичный сброс возможен через MQTT команду в топик `{prefix}/c/system/reset = 1` или через веб-интерфейс `/resetall`, если при компиляции были объявлены константы `MQTT_RESET_ENABLED` и `WEB_RESET_ENABLED`

**Обновление прошивки** — в любом из режимов на веб-интерфейсе имеется возможность выполнить обновление прошивки по воздуху (OTA). После обновления устройство автоматически перезагружается. Это единственный способ обновления при установке устройства в вентиляционном канале.

**Потеря соединения при выключении питания** — когда устройство обесточено (или когда брокер перестаёт получать обновления статуса), срабатывает LWT-механизм, сбрасывающий состояние `status` → `Offline`.

**Примечание:** При потере соединения/отключении состояние исполнительного механизма в логике умного дома не сбрасывается автоматически; при необходимости следует реализовать это на стороне контроллера (например, правило в OpenHAB).

## Топики MQTT

**Общие топики (для всех типов):**

| Топик | Направление | Описание |
|-------|-------------|----------|
| `{prefix}/status` | Устройство → Брокер | Статус устройства: `Online` / `Offline` (LWT) |
| `{prefix}/c/system/reset` | Брокер → Устройство | Сброс к заводским настройкам (`1`) |

**Топики для DEVICE_TYPE 1 и 3 (исполнительное устройство):**

| Топик | Направление | Описание |
|-------|-------------|----------|
| `{prefix}/fan/state` или `{prefix}/switch/state` | Устройство → Брокер | Состояние: `ON` / `OFF` |
| `{prefix}/c/fan/state` или `{prefix}/c/switch/state` | Брокер → Устройство | Прямое управление: `ON` / `OFF` |
| `{prefix}/fan/pwmDuty` или `{prefix}/switch/pwmDuty` | Устройство → Брокер | Текущая скважность ШИМ (0-100) |
| `{prefix}/c/fan/pwmDuty` или `{prefix}/c/switch/pwmDuty` | Брокер → Устройство | Установка скважности ШИМ (0-100). При ручном изменении адаптивный режим отключается (только TYPE 1), значение НЕ сохраняется в EEPROM |
| `{prefix}/fan/delaySec` или `{prefix}/switch/delaySec` | Устройство → Брокер | Настроенное значение задержки отложенного включения в секундах |
| `{prefix}/c/fan/delaySec` или `{prefix}/c/switch/delaySec` | Брокер → Устройство | Установка задержки отложенного включения в секундах |
| `{prefix}/fan/maxOnTime` или `{prefix}/switch/maxOnTime` | Устройство → Брокер | Настроенное значение аварийного отключения в секундах |
| `{prefix}/c/fan/maxOnTime` или `{prefix}/c/switch/maxOnTime` | Брокер → Устройство | Установка времени аварийного отключения в секундах (0 — отключено) |

**Топики только для DEVICE_TYPE 1:**

| Топик | Направление | Описание |
|-------|-------------|----------|
| `{prefix}/fan/adaptiveMode` | Устройство → Брокер | Адаптивный тихий режим: `1` / `0` |
| `{prefix}/c/fan/adaptiveMode` | Брокер → Устройство | Включение/выключение адаптивного режима |
| `{prefix}/fan/sensorControlMode` | Устройство → Брокер | Режим управления сенсором: `1` / `0` |
| `{prefix}/c/fan/sensorControlMode` | Брокер → Устройство | Переключение режима: `AUTO` / `1` — режим управления сенсором, `0` — ручной |

**Топики для DEVICE_TYPE 1 и 2 (датчик):**

| Топик | Направление | Описание |
|-------|-------------|----------|
| `{prefix}/sensor/temperature` | Устройство → Брокер | Температура (°C) |
| `{prefix}/sensor/humidity` | Устройство → Брокер | Влажность (%) |

**Топики только для DEVICE_TYPE 1 (пороги датчика):**

| Топик | Направление | Описание |
|-------|-------------|----------|
| `{prefix}/sensor/lowTemp` | Устройство → Брокер | Нижний порог температуры |
| `{prefix}/c/sensor/lowTemp` | Брокер → Устройство | Установка нижнего порога температуры |
| `{prefix}/sensor/highTemp` | Устройство → Брокер | Верхний порог температуры |
| `{prefix}/c/sensor/highTemp` | Брокер → Устройство | Установка верхнего порога температуры |
| `{prefix}/sensor/lowHum` | Устройство → Брокер | Нижний порог влажности |
| `{prefix}/c/sensor/lowHum` | Брокер → Устройство | Установка нижнего порога влажности |
| `{prefix}/sensor/highHum` | Устройство → Брокер | Верхний порог влажности |
| `{prefix}/c/sensor/highHum` | Брокер → Устройство | Установка верхнего порога влажности |
| `{prefix}/fan/sensorControlMode` или `{prefix}/switch/sensorControlMode` | Устройство → Брокер | Режим управления сенсором: `1` / `0` |
| `{prefix}/c/fan/sensorControlMode` или `{prefix}/c/switch/sensorControlMode` | Брокер → Устройство | Переключение режима: `AUTO` / `1` — режим управления 
**Примечания:**

1. **Топик `pwmDuty`** публикует текущую скважность в процентах (0-100). Значение 100 означает полную мощность (тихий режим выключен).
2. **При прямом управлении** (команда в `controlTopic`) устройство автоматически переходит в ручной режим (`sensorControlMode = false`).
3. **При ручном изменении скважности** через `pwmDutyControlTopic` адаптивный режим автоматически отключается, значение НЕ сохраняется в EEPROM.
4. **При выключении вентилятора** скважность восстанавливается до сохранённого в EEPROM значения (настройки пользователя).
5. **Сохранение в EEPROM** происходит ТОЛЬКО через веб-форму настроек (`/config` + `/save`).
6. **Сброс настроек** через MQTT (`/c/system/reset = 1`) доступен только если при компиляции определён макрос `MQTT_RESET_ENABLED = 1`. После сброса устройство перезагружается в режим настройки (точка доступа).

## Конфигурационные параметры

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| `pwmDutyPercent` | uint16_t | 100 | Скважность ШИМ (0-100%). 100 = полная мощность |
| `adaptiveMode` | bool | false | Адаптивный тихий режим (только TYPE 1) |
| `sensorControlMode` | bool | true | Режим управления сенсором (заменяет `automaticMode`) |
| `MIN_PWM_DUTY_PERCENT` | константа | 10 | Минимальная скважность при адаптации |
| `ADAPTIVE_EPSILON_TEMP` | константа | 0.5 | Порог изменения температуры для адаптации (°C) |
| `ADAPTIVE_EPSILON_HUM` | константа | 2.0 | Порог изменения влажности для адаптации (%) |
| `ADAPTIVE_STEP_SIZE` | константа | 10 | Базовый шаг изменения скважности при адаптации (%) |
| `PWM_STARTING` | константа | 2000 | Длительность стартового импульса (мс) |
