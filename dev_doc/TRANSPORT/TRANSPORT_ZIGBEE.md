## 1. Назначение

`TRANSPORT_ZIGBEE` — реализация транспортной абстракции для Zigbee Mesh-сети. Это **самовосстанавливающаяся сущность**, которая обеспечивает постоянный канал связи между устройством и Zigbee-координатором (шлюзом).

**Zigbee-транспорт объединяет:**
- **Среду:** Zigbee (IEEE 802.15.4)
- **Прикладной протокол:** ZCL (Zigbee Cluster Library)

**Zigbee-транспорт управляет:**
- Присоединением к Zigbee-сети (автоматическое, через Permit Join)
- Регистрацией конечных точек (Endpoints) и кластеров
- Отчётами атрибутов (Reporting)
- Обработкой входящих ZCL-команд

**Zigbee-транспорт устанавливает флаги в `StateProvider`:**
- `link_ok` — присоединён к Zigbee-сети
- `gateway_ok` — координатор доступен
- `setup_mode` — режим настройки активен

**Zigbee-транспорт НЕ управляет:**
- Бизнес-логикой устройства (это DeviceController)

## 4. Режимы работы

| Режим | Состояние Zigbee | Назначение |
|-------|------------------|------------|
| **Обычный** | Присоединён к сети | Работа в сети |
| **Настройка** | Поиск сети (Permit Join) | Сбор данных |

### 4.1. Обычный режим

- Устройство присоединено к Zigbee-сети
- Конечные точки зарегистрированы
- Атрибуты публикуются через Reporting
- Команды принимаются через ZCL

### 4.2. Режим настройки

- Устройство сканирует доступные сети
- При обнаружении координатора с активным Permit Join — автоматически присоединяется
- После присоединения — переключение в обычный режим

### 4.3. Переключение между режимами

```
Обычный режим
    │
    │ Потеря сети / нет сети
    ▼
Режим настройки (поиск)
    │
    │ Присоединение к сети
    ▼
Обычный режим
```

**Переключение выполняется транспортом автоматически:**
1. При старте: если нет сети → режим настройки
2. В процессе: потеря сети → переподключение → если не удаётся → режим настройки
3. После присоединения: проверка → успех → обычный режим

## 6. Управление настройкой

Zigbee-транспорт сам управляет процессом настройки (присоединения к сети).

### 6.1. Кто принимает решение

**Zigbee-транспорт** — единственный, кто решает, когда переключиться в режим настройки.

**Условия для переключения в режим настройки:**
1. **При старте:** если нет присоединения к сети → `setMode(true)`
2. **В процессе работы:** если потеряна связь с сетью → попытки переподключения → если не удаётся → `setMode(true)`


### 6.2. Управление режимами

```cpp
void ZigbeeTransport::setMode(bool setupMode) {
    if (setupMode) {
        // ===== РЕЖИМ НАСТРОЙКИ (поиск сети) =====
        XLOG_INFO(CAT_ZIGBEE, "Switching to SETUP mode (scanning)");
        
        _state = STATE_SETUP_MODE;
        _connected = false;
        
        // Обновляем флаги
        StateProvider::getInstance().set_setup_mode(true);
        StateProvider::getInstance().set_link_ok(false);
        StateProvider::getInstance().set_gateway_ok(false);
        
        // Запускаем сканирование
        zigbee_start_setup();
        
    } else {
        // ===== ОБЫЧНЫЙ РЕЖИМ (подключён) =====
        XLOG_INFO(CAT_ZIGBEE, "Switching to NORMAL mode (connected)");
        
        _state = STATE_NORMAL;
        _connected = true;
        
        // Обновляем флаги
        StateProvider::getInstance().set_setup_mode(false);
        StateProvider::getInstance().set_link_ok(true);
        StateProvider::getInstance().set_gateway_ok(true);
        
        // Регистрируем endpoints
        registerEndpoints();
    }
}
```

### 6.3. Инструменты настройки

- **Permit Join** — автоматическое присоединение к координатору
- Координатор должен иметь активный Permit Join
- Устройство сканирует сети и присоединяется к первой доступной

### 6.4. Проверка данных

- После присоединения — транспорт проверяет наличие сети
- Проверяет регистрацию endpoints
- Проверяет возможность отправки отчётов

### 6.5. Остановка настройки

Транспорт останавливает настройку когда:
- Устройство успешно присоединилось к сети
- Endpoints зарегистрированы

## 7. Взаимодействие с компонентами

### 7.1. Управление стеком

Транспорт управляет Zigbee-стеком через публичный интерфейс:

| Метод | Назначение |
|-------|------------|
| `zigbee_init()` | Инициализация стека |
| `zigbee_begin(config)` | Запуск стека с конфигурацией |
| `zigbee_update()` | Периодическая обработка |
| `zigbee_start_setup()` | Запуск сканирования сетей (Permit Join) |

### 7.2. Регистрация Endpoints

```cpp
void ZigbeeTransport::registerEndpoints() {
    // Endpoint 1 — Управление (TYPE 1, 3)
    zigbee_register_endpoint(1, DEVICE_TYPE_FAN, &on_off_cluster, &level_cluster);
    
    // Endpoint 2 — Датчик (TYPE 1, 2)
    zigbee_register_endpoint(2, DEVICE_TYPE_SENSOR, &temperature_cluster, &humidity_cluster);
    
    // Endpoint 3 — Конфигурация (Все типы)
    zigbee_register_endpoint(3, DEVICE_TYPE_CONFIG, &basic_cluster, &custom_cluster);
}
```

### 7.3. Публикация данных

```cpp
void ZigbeeTransport::publishState(const DeviceState* state) {
    if (!_connected) return;
    
    // Endpoint 1 — Управление
    zigbee_update_attribute(1, 0x0006, 0x0000, state->is_on ? 1 : 0);
    zigbee_update_attribute(1, 0x0008, 0x0000, state->speed);
    
    // Endpoint 2 — Датчик
    zigbee_update_attribute(2, 0x0402, 0x0000, state->temperature * 100);
    zigbee_update_attribute(2, 0x0405, 0x0000, state->humidity * 100);
}
```

### 7.4. Обработка команд

```cpp
void ZigbeeTransport::onZclCommand(uint8_t endpoint, uint16_t cluster, uint8_t command, void* data) {
    TransportCommand cmd;
    TransportCommandData cmdData;
    
    switch (cluster) {
        case 0x0006:  // On/Off
            cmd = CMD_STATE;
            cmdData.boolVal = (command == 0x01);
            break;
        case 0x0008:  // Level Control
            cmd = CMD_SPEED;
            cmdData.intVal = *(uint8_t*)data;
            break;
        // ...
    }
    
    _commandCallback(cmd, &cmdData);
}
```

### 7.5. Обработка изменения конфигурации

```cpp
void ZigbeeTransport::onConfigUpdate(const TransportConfig* config) {
    if (config->zigbeePanId != _currentPanId) {
        _zigbeeStack.reset();
        _zigbeeStack.begin(config);
        setMode(true);  // Перезапускаем присоединение
    }
}
```

## 8. Управление флагами состояния

Zigbee-транспорт устанавливает флаги в `StateProvider`:

| Флаг | Кто устанавливает | Когда |
|------|-------------------|-------|
| `link_ok` | Zigbee-транспорт | Присоединён к сети |
| `gateway_ok` | Zigbee-транспорт | Координатор доступен |
| `setup_mode` | Zigbee-транспорт | Режим настройки активен |

```cpp
void ZigbeeTransport::updateFlags() {
    // Флаги обновляются внутри setMode()
    // Дополнительные проверки для gateway_ok
    bool coordinatorOk = zigbee_is_coordinator_available();
    StateProvider::getInstance().set_gateway_ok(coordinatorOk);
}
```
