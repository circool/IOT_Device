## 2. Конечные точки (Endpoints)

Устройство представляет **четыре конечные точки**:

| Endpoint | Device Type | ID | Применимость |
|----------|-------------|-----|--------------|
| **0** | Aggregator | 0x000E | Все типы (корневая точка) |
| **1** | Extended Color Light | 0x010D | TYPE 1, 3 |
| **2** | Temperature Sensor | 0x0302 | TYPE 1, 2 |
| **3** | Humidity Sensor | 0x0307 | TYPE 1, 2 |

**Примечание:** Extended Color Light используется вместо Fan, так как спецификация Matter не включает отдельный тип для вентилятора. Управление скоростью реализуется через атрибут `CurrentLevel`.

## 3. Кластеры и атрибуты

### 3.1. Endpoint 0 — Aggregator (все типы)

| Кластер | ID | Назначение |
|---------|-----|------------|
| **Basic Information** | 0x0028 | `VendorName`, `ProductName`, `SoftwareVersion` |
| **OTA Software Update** | 0x002A | Обновление прошивки |
| **Custom (пользовательский)** | 0xFC00 | Пороги, таймеры, режимы |

**Пользовательский кластер (0xFC00) на Endpoint 0:**

| Атрибут | ID | Тип | Назначение |
|---------|-----|-----|------------|
| `SensorControlMode` | 0x0000 | bool | SENSOR / MANUAL |
| `AdaptiveMode` | 0x0001 | bool | Адаптивный режим |
| `LowTemp` | 0x0002 | int16 | Нижний порог температуры (°C × 100) |
| `HighTemp` | 0x0003 | int16 | Верхний порог температуры (°C × 100) |
| `LowHum` | 0x0004 | uint16 | Нижний порог влажности (% × 100) |
| `HighHum` | 0x0005 | uint16 | Верхний порог влажности (% × 100) |
| `DelaySeconds` | 0x0006 | uint16 | Задержка включения (сек) |
| `MaxOnTime` | 0x0007 | uint32 | Аварийное отключение (сек) |
| `BootState` | 0x0008 | bool | Состояние при старте |

### 3.2. Endpoint 1 — Extended Color Light (TYPE 1, 3)

| Кластер | ID | Обязательность | Атрибуты и команды |
|---------|-----|---------------|-------------------|
| **Identify** | 0x0003 | Обязательный | `Identify` — визуальная идентификация |
| **On/Off** | 0x0006 | Обязательный | `OnOff` — состояние; команды `On`, `Off`, `Toggle` |
| **Level Control** | 0x0008 | Обязательный | `CurrentLevel` — скорость (0-100%); команда `MoveToLevel` |
| **Groups** | 0x0004 | Обязательный | Групповое управление |

### 3.3. Endpoint 2 — Temperature Sensor (TYPE 1, 2)

| Кластер | ID | Обязательность | Атрибуты |
|---------|-----|---------------|----------|
| **Temperature Measurement** | 0x0402 | Обязательный | `MeasuredValue` — температура (°C × 100) |

### 3.4. Endpoint 3 — Humidity Sensor (TYPE 1, 2)

| Кластер | ID | Обязательность | Атрибуты |
|---------|-----|---------------|----------|
| **Relative Humidity Measurement** | 0x0405 | Обязательный | `MeasuredValue` — влажность (% × 100) |

### 3.5. Общие кластеры (все Endpoints)

| Кластер | ID | Назначение |
|---------|-----|------------|
| **Descriptor** | 0x001D | Идентификация типа устройства и состава конечной точки |

## 4. Типы взаимодействия

| Кластер | Публикация | Управление | Механизм |
|---------|-----------|------------|----------|
| **On/Off** | ✅ Да | ✅ Да | Подписка на `OnOff` + команды `On`/`Off` |
| **Level Control** | ✅ Да | ✅ Да | Подписка на `CurrentLevel` + команда `MoveToLevel` |
| **Temperature Measurement** | ✅ Да | ❌ Нет | Подписка на `MeasuredValue` |
| **Relative Humidity** | ✅ Да | ❌ Нет | Подписка на `MeasuredValue` |
| **Basic Information** | ✅ Да | ❌ Нет | Статические атрибуты |
| **OTA Software Update** | ❌ Нет | ✅ Да | Приём обновлений от контроллера |
| **Custom (0xFC00)** | ✅ Да | ✅ Да | Подписка на атрибуты + `WriteAttribute` |

## 5. Подписки (Subscriptions)

Matter использует модель **подписок** вместо периодической публикации:

1. Контроллер подписывается на атрибуты устройства
2. Устройство отправляет начальные значения при подписке
3. При изменении атрибута устройство отправляет обновление
4. Подписка поддерживается через регулярные keep-alive сообщения

**Особенности:**
- Подписки заменяют периодическую публикацию (как в MQTT)
- Не нужно настраивать интервалы отчётов (как в Zigbee)
- Контроллер сам определяет, на какие атрибуты подписываться

## 6. Команды

### 6.1. Команды управления (Endpoint 1)

| Кластер | Команда | Параметр | Назначение |
|---------|---------|----------|------------|
| On/Off | `On` | — | Включить |

## 7. Commissioning

Настройка выполняется через стандартную процедуру комиссионинга:

1. **QR-код** — сканируется приложением экосистемы
2. **Числовой код** — вводится вручную (11 цифр)
3. Устройство подключается к WiFi/Thread сети
4. Устройство регистрируется в экосистеме

**Интеграция с режимом настройки:**

```
1. Транспорт переходит в режим настройки (setMode(true))
2. Устройство начинает ожидать Commissioning
3. Пользователь сканирует QR-код на устройстве
4. Контроллер передаёт учётные данные сети
5. Устройство подключается к сети
6. Устройство регистрируется в Matter-контроллере
7. Транспорт переключается в обычный режим (setMode(false))
8. Контроллер подписывается на атрибуты
```
