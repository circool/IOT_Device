## 1. Назначение

Документ описывает **строгий порядок инициализации** слоёв и их вызова в `loop()`.

**Цель:** Исключить ошибки, связанные с неправильным порядком вызовов (например, вызов `transport->update()` до инициализации DeviceController).

---

## 2. Порядок инициализации в setup()

```cpp
void setup() {
    // ============================================================
    // 1. БАЗОВЫЕ СЛОИ (не зависят от других)
    // ============================================================
    
    // 1.1. Логгер — должен быть самым первым
    Logger::getInstance().init((LogLevel)XLOG_LEVEL, XLOG_CATEGORIES, XLOG_USE_COLOR);
    
    // 1.2. Аппаратная инициализация (кнопка, LED, WDT)
    wdt_init();
    button_init();
    led_init();
    
    // ============================================================
    // 2. КОНФИГУРАЦИЯ (загрузка из EEPROM)
    // ============================================================
    
    // 2.1. ConfigManager — загружает все настройки
    g_configManager.init();
    
    // ============================================================
    // 3. БИЗНЕС-ЛОГИКА (DeviceController)
    // ============================================================
    
    // 3.1. DeviceController — инициализируется с настройками
    DeviceController::getInstance().init(g_configManager.get());
    
    // ============================================================
    // 4. ТРАНСПОРТ
    // ============================================================
    
    // 4.1. Создаём транспорт через фабрику
    g_transport = createTransport();
    if (!g_transport) {
        XLOG_ERROR(CAT_MAIN, "Failed to create transport!");
        return;
    }
    
    // 4.2. Передаём конфигурацию
    g_transport->begin(g_configManager.getTransportConfig());
    
    // 4.3. Регистрируем колбэки
    g_transport->onCommand(onTransportCommand);
    g_transport->onConfigUpdate(onTransportConfigUpdate);
    
    // ============================================================
    // 5. ПРОВЕРКА
    // ============================================================
    
    XLOG_INFO(CAT_MAIN, "Setup complete. Transport %s",
              g_transport->isConnected() ? "CONNECTED" : "DISCONNECTED");
}
```

**Почему именно такой порядок:**

| Этап | Почему сначала |
|------|----------------|
| **Логгер** | Логи должны быть доступны с самого начала |
| **Железо** | Не зависит от других слоёв |
| **ConfigManager** | Настройки нужны для DeviceController и транспорта |
| **DeviceController** | Должен быть готов до транспорта (транспорт вызывает колбэки) |
| **Транспорт** | Зависит от ConfigManager (конфиг) и DeviceController (колбэки) |

## 3. Порядок обработки в loop()

```cpp
void loop() {
    // ============================================================
    // 1. СТОРОЖЕВОЙ ТАЙМЕР (аппаратный)
    // ============================================================
    wdt_feed();
    
    // ============================================================
    // 2. КНОПКА (аппаратный ввод)
    // ============================================================
    button_update();
    
    // ============================================================
    // 3. ТРАНСПОРТ (приём команд, публикация)
    // ============================================================
    if (g_transport) {
        g_transport->update();
    }
    
    // ============================================================
    // 4. БИЗНЕС-ЛОГИКА (обработка команд, управление актуатором)
    // ============================================================
    DeviceController::getInstance().update();
    
    // ============================================================
    // 5. ИНДИКАЦИЯ (LED)
    // ============================================================
    led_update();
    
    // ============================================================
    // 6. ПЕРЕЗАГРУЗКА (если запрошена)
    // ============================================================
    restart_update();
}
```

**Почему именно такой порядок:**

| Этап | Почему |
|------|--------|
| **WDT** | Должен быть самым первым (защита от зависаний) |
| **Кнопка** | Аппаратный ввод — должен обрабатываться в начале цикла |
| **Транспорт** | Должен принять команды до того, как DeviceController начнёт их обрабатывать |
| **DeviceController** | Обрабатывает команды, полученные от транспорта |
| **LED** | Отображает состояние, которое обновил DeviceController |
| **Restart** | В самом конце — если запрошена перезагрузка |

---

## 4. Диаграмма последовательности

```
setup():
    Logger → ConfigManager → DeviceController → Transport
    
loop():
    Transport::update() → DeviceController::update() → LED::update()
```

**Взаимодействие через колбэки:**

```
Transport → onCommand() → DeviceController
Transport → onConfigUpdate() → ConfigManager
DeviceController → publishState() → Transport
```

---

## 5. Зависимости

| Компонент | Зависит от |
|-----------|------------|
| **Logger** | — |
| **ConfigManager** | Logger |
| **DeviceController** | ConfigManager, TransportState |
| **Transport** | ConfigManager, TransportState, DeviceController (через колбэки) |
| **LED** | TransportState |

**Важно:** Transport не должен зависеть от DeviceController напрямую — только через колбэки.

---

## 6. Ошибки и их обработка

| Ошибка | Причина | Решение |
|--------|---------|---------|
| `transport->update()` до инициализации | Транспорт не создан | Проверить `if (g_transport)` перед вызовом |
| `DeviceController` не обрабатывает команды | Колбэк не зарегистрирован | Проверить `g_transport->onCommand()` в `setup()` |
| LED показывает неправильное состояние | TransportState не обновлён | Проверить, что транспорт обновляет `link_ok` и `setup_mode` |
