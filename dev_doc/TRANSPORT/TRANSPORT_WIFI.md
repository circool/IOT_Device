## 1. Назначение

`TRANSPORT_WIFI` — реализация транспортной абстракции для среды WiFi. Это **самовосстанавливающаяся сущность**, которая обеспечивает постоянный канал связи между устройством и внешним миром через WiFi-сеть.

**WiFi-транспорт объединяет:**
- **Среду:** WiFi (STA / AP)
- **Прикладные протоколы:** HTTP, MQTT
- **Инструменты настройки:** BLE (опционально, только в режиме настройки)

**WiFi-транспорт управляет:**
- Режимами WiFi (STA / AP)
- Прикладными протоколами (HTTP, MQTT) — напрямую
- BLE-сервером (в режиме настройки)

**WiFi-транспорт устанавливает флаги в `TransportState`:**
- `link_ok` — состояние WiFi-среды
- `link_quality` — уровень сигнала (RSSI)
- `setup_mode` — режим настройки активен

**WiFi-транспорт НЕ управляет:**
- Бизнес-логикой устройства (это DeviceController)
- Флагом `gateway_ok` — это ответственность MQTT-протокола

## 3. Компоненты

| Компонент | Назначение | Активен в обычном режиме | Активен в режиме настройки |
|-----------|------------|--------------------------|----------------------------|
| **WiFi STA** | Подключение к роутеру | ✅ | ❌ |
| **WiFi AP** | Точка доступа для настройки | ❌ | ✅ |
| **HTTP-протокол** | Веб-интерфейс (состояние / настройка) | ✅ | ✅ |
| **MQTT-протокол** | Публикация и команды | ✅ | ❌ |
| **BLE-сервер** | Сбор данных через ESP BLE Provisioning | ❌ | ✅ (опционально) |

**Важно:** HTTP и MQTT — равноправные прикладные протоколы. Оба получают данные через `publishState()` / `publishSettings()`.

## 4. Режимы работы

| Режим | WiFi | HTTP | MQTT | BLE | Назначение |
|-------|------|------|------|-----|------------|
| **Обычный** | STA | Страница состояния | ✅ Работает | ❌ | Работа в сети |
| **Настройка** | AP | Страница ввода | ❌ | ✅ (опционально) | Сбор данных |

### 4.1. Обычный режим

- WiFi подключён к роутеру
- HTTP показывает страницу состояния (из кэша `publishState()`)
- MQTT активен, получает данные через `publishState()`
- BLE выключен
- Транспорт принимает команды и публикует состояние

### 4.2. Режим настройки

- WiFi создаёт точку доступа
- HTTP показывает страницу ввода учётных данных
- MQTT выключен
- BLE активен (если включён в сборке)

### 4.3. Переключение между режимами

```
Обычный режим
    │
    │ Потеря связи / нет конфигурации
    ▼
Режим настройки
    │
    │ Получены и проверены данные
    ▼
Обычный режим
```

**Переключение выполняется транспортом автоматически:**
1. При старте: если нет конфигурации → режим настройки
2. В процессе: потеря связи → попытки переподключения → если не удаётся → режим настройки
3. После получения данных: проверка → успех → обычный режим

## 5. Жизненный цикл

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. begin(config)                                                            │
│    • Проверить конфигурацию (SSID/пароль)                                   │
│    • Если есть → попытаться подключиться (асинхронно)                       │
│    • Если нет → сразу переключиться в режим настройки                       │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 2. update() — вызывается в loop()                                           │
│                                                                             │
│    А. Если режим настройки:                                                 │
│       • Обработать HTTP-запросы (страница ввода)                            │
│       • Обработать BLE-события (если включён)                               │
│       • Если данные получены → проверить их (подключение к WiFi)            │
│       • Если валидны → переключиться в обычный режим                        │
│       • Если невалидны → продолжить режим настройки                         │
│                                                                             │
│    Б. Если обычный режим:                                                   │
│       • Поддерживать WiFi-соединение                                        │
│       • Поддерживать MQTT-соединение                                        │
│       • Обрабатывать HTTP-команды                                           │
│       • При изменении состояния → publishState() для всех протоколов        │
│       • При потере связи → попытки переподключения                          │
│       • При невозможности → переключиться в режим настройки                 │
│                                                                             │
│    В. Если подключение в процессе:                                          │
│       • Проверять статус WiFi                                               │
│       • При успехе → переключиться в обычный режим                          │
│       • При таймауте → переключиться в режим настройки                      │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 6. Управление настройкой

WiFi-транспорт сам управляет процессом настройки (получения учётных данных).

### 6.1. Запуск настройки

Транспорт запускает настройку когда:
- Нет сохранённой конфигурации
- Потеряна связь и переподключение невозможно
- Таймаут подключения к указанной сети

### 6.2. Инструменты настройки

В зависимости от настроек компиляции (`USE_BLE_SETUP`, `USE_AP_SETUP`), транспорт может использовать:
- **AP + HTTP** — страница ввода
- **BLE** — ESP BLE Provisioning
- Оба инструмента одновременно

### 6.3. Проверка данных

При получении данных (SSID/пароль) транспорт:
1. Пытается подключиться к указанной сети
2. При успехе → переключается в обычный режим
3. При ошибке → продолжает сбор данных

### 6.4. Остановка настройки

Транспорт останавливает настройку когда:
- Получены валидные данные
- Транспорт успешно подключился к WiFi

## 7. Взаимодействие с компонентами

WiFi-транспорт управляет прикладными протоколами напрямую, через их публичные методы.

### 7.1. Управление протоколами

Транспорт вызывает методы протоколов для переключения режимов:

```cpp
void WiFiTransport::setMode(bool setupMode) {
  if (setupMode) {
    // 1. Переключаем WiFi
    WiFi.mode(WIFI_AP);
    WiFi.softAP(_deviceId);
    
    // 2. Управляем протоколами напрямую
    _http.setMode(HTTP_MODE_SETUP);    // Страница ввода
    _mqtt.setEnabled(false);           // Остановить MQTT
    _ble.start();                      // Запустить BLE (если включён)
    
    // 3. Устанавливаем флаги в TransportState// @deprecated StateProvider see TransportState
    TransportState::getInstance().set_setup_mode(true);// @deprecated StateProvider see TransportState
    StateProvider::getInstance().set_link_ok(false);  // AP не считается link_ok // @deprecated StateProvider see TransportState
  } else {
    WiFi.mode(WIFI_STA);
    WiFi.begin(_config.wifiSsid, _config.wifiPassword);
    
    _http.setMode(HTTP_MODE_NORMAL);   // Страница состояния
    _mqtt.setEnabled(true);            // Запустить MQTT
    _ble.stop();                       // Остановить BLE
    
    // link_ok будет установлен после успешного подключения
  }
}

```

### 7.2. Публикация данных

При изменении состояния устройства транспорт публикует данные всем протоколам:

```cpp
void WiFiTransport::publishState(const DeviceState* state) {
    #ifdef USE_HTTP
        _http.updateState(state);   // HTTP кэширует состояние
    #endif
    
    #ifdef USE_MQTT
        _mqtt.publishState(state);  // MQTT публикует в топики
    #endif
}
```

### 7.3. Управление HTTP-протоколом

Транспорт управляет HTTP-протоколом через его публичный интерфейс:

| Метод | Назначение |
|-------|------------|
| `http_set_mode(mode)` | Переключить режим (NORMAL / SETUP) |
| `http_set_fields(fields)` | Установить, какие поля показывать на странице |
| `http_prefill_config(config)` | Предзаполнить поля известными данными |
| `http_update_state(state)` | Обновить состояние для отображения |

### 7.4. Управление MQTT-протоколом

Транспорт управляет MQTT-протоколом через его публичный интерфейс:

| Метод | Назначение |
|-------|------------|
| `mqtt_begin(config)` | Запустить MQTT-клиент |
| `mqtt_set_enabled(enabled)` | Включить/выключить MQTT |
| `mqtt_update()` | Периодическая обработка |
| `mqtt_publish_state(state)` | Публикация состояния |

### 7.5. Управление BLE-сервером

Транспорт управляет BLE-сервером через его публичный интерфейс:

| Метод | Назначение |
|-------|------------|
| `ble_start(device_id)` | Запустить BLE-сервер |
| `ble_stop()` | Остановить BLE-сервер |
| `ble_update()` | Периодическая обработка |

**Важно:** BLE-сервер активен **только в режиме настройки** и только если `USE_BLE_SETUP == 1`.

### 7.6. Управление флагами состояния

WiFi-транспорт устанавливает в `TransportState` только флаги, относящиеся к среде:

| Флаг | Кто устанавливает | Когда |
|------|-------------------|-------|
| `link_ok` | WiFi-транспорт | WiFi STA подключён к роутеру |
| `link_quality` | WiFi-транспорт | При изменении RSSI |
| `setup_mode` | WiFi-транспорт | Режим настройки активен |
| `gateway_ok` | **MQTT-протокол** | MQTT подключён к брокеру |

**Принцип:** Каждый компонент устанавливает только свои флаги. WiFi-транспорт не знает о MQTT, MQTT-протокол не знает о WiFi.

**Примечание:** HTTP не управляет `gateway_ok`, потому что он не является внешним сервисом для устройства, а лишь визуальным интерфейсом поверх сети. Его работа полностью зависит от `link_ok`.

```cpp
void WiFiTransport::updateFlags() {
    bool wifiOk = (WiFi.status() == WL_CONNECTED);
    StateProvider::getInstance().set_link_ok(wifiOk);// @deprecated StateProvider see TransportState
    
    if (wifiOk) {
        StateProvider::getInstance().set_link_quality(WiFi.RSSI());// @deprecated StateProvider see TransportState
    }
    
    // gateway_ok устанавливает MQTT-протокол, не WiFi-транспорт
}
```

## 8. Флаги компиляции

| Внутренний флаг | Назначение |
|-----------------|------------|
| `USE_WIFI` | Включить WiFi-транспорт |
| `USE_MQTT` | Включить MQTT-протокол |
| `USE_HTTP` | Включить HTTP-протокол |
| `USE_BLE_SETUP` | Включить BLE-сервер для режима настройки |
| `USE_AP_SETUP` | Включить AP-режим для настройки |

**Таблица соответствия:**

| Метод настройки | `USE_BLE_SETUP` | `USE_AP_SETUP` |
|----------------|---------------|--------------|
| Нет | 0 | 0 |
| BLE | 1 | 0 |
| AP | 0 | 1 |
| BLE + AP | 1 | 1 |

**Примечание:** `USE_HTTP` = 1 всегда для WiFi-транспорта.
