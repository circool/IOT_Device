## 1. Назначение

Слой `wifi_manager` обеспечивает **только STA-режим** (клиент):

- **Подключение к WiFi** — подключение к существующей сети
- **Мониторинг** — отслеживание состояния подключения
- **Автопереподключение** — восстановление связи при потере
- **Сигнализация состояния** — управление флагом `STATE_WIFI_OK` на основе анализа успешности попыток подключения

**Важно:** 
- `wifi_manager` — **единственный слой в проекте**, который управляет битом `STATE_WIFI_OK`. Никакой другой слой не имеет права устанавливать или снимать этот флаг.

---

## 2. Архитектурные решения

| # | Решение | Обоснование |
|---|---------|-------------|
| 1 | **`wifi_manager` — единственный владелец `STATE_WIFI_OK`** | Централизованное управление состоянием подключения. Другие слои только читают этот флаг |
| 2 | **Логика сигнализации состояния — ответственность менеджера** | WiFi-менеджер анализирует результаты попыток подключения и на основе этого устанавливает или снимает `STATE_WIFI_OK`. Оркестратор не участвует в этом анализе |

---

## 3. Принцип работы

### Инициализация (`wifi_manager_init()`)
- Настройка WiFi-стека в режим STA
- Регистрация обработчиков событий WiFi
- Запуск автоматического подключения (если есть SSID в Config)

### Периодическая обработка (`wifi_manager_update()`)

| Шаг | Действие | Влияние на `STATE_WIFI_OK` |
|-----|----------|---------------------------|
| 1 | Проверка состояния подключения | — |
| 2 | Если WiFi подключён — сбросить все таймеры и счётчики | **Установить** `STATE_WIFI_OK` |
| 3 | Если WiFi отключён — запустить процесс переподключения | **Оставить** `STATE_WIFI_OK` установленным |
| 4 | При успешном переподключении — сбросить счётчики | **Оставить** `STATE_WIFI_OK` установленным |
| 5 | При неудачной попытке — увеличить счётчик | **Оставить** `STATE_WIFI_OK` установленным |
| 6 | При исчерпании попыток — зафиксировать таймаут | **Снять** `STATE_WIFI_OK` |

---

## 4. API

| Метод | Назначение | Вызов |
|-------|------------|-------|
| `wifi_manager_init()` | Инициализация WiFi-стека | Один раз в `setup()` |
| `wifi_manager_update()` | Периодическая обработка состояния | Каждый `loop()` |
| `wifi_manager_connect(ssid, password)` | Запуск асинхронного подключения к сети | По требованию |
| `wifi_get_local_ip()` | Получение IP-адреса | По требованию |
| `wifi_get_rssi()` | Получение уровня сигнала (RSSI) | По требованию |
| `wifi_scan_and_log(targetSsid)` | Сканирование сетей (отладка) | По требованию |

**Правила:**
- Методы должны быть неблокирующие (асинхронные), если это возможно
- `wifi_scan_and_log()` — **синхронный блокирующий**, используется **только для отладки**, в production отключён

## 5. Интеграция с SystemState

| Событие | Действие | Ответственный |
|---------|----------|---------------|
| WiFi подключён (`WL_CONNECTED`) | Установить `STATE_WIFI_OK` | **Только** `wifi_manager` |
| WiFi отключён, процесс переподключения активен | **Оставить** `STATE_WIFI_OK` установленным | **Только** `wifi_manager` |
| Исчерпаны попытки переподключения или таймаут | Снять `STATE_WIFI_OK` | **Только** `wifi_manager` |

## 6. Константы и настройка через build_flags

### 6.1.1. Константы WiFi-менеджера

Эти константы (из значения по умолчанию) помещены в `wifi_manager`

| Константа | Тип | Значение по умолчанию | Описание |
|-----------|-----|----------------------|----------|
| `WIFI_RECONNECT_ATTEMPTS` | `int` | 5 | Количество попыток переподключения перед снятием `STATE_WIFI_OK` |
| `WIFI_RECONNECT_INTERVAL_MS` | `int` | 5000 | Интервал между попытками переподключения (мс) |
| `WIFI_CONNECT_TIMEOUT_MS` | `int` | 15000 | Таймаут ожидания подключения (мс) |

### 6.1.2. Константы задаваемые пользователем

Эти константы (из значения по умолчанию) помещены в `settings.h`

| Константа | Тип | Значение по умолчанию | Описание |
|-----------|-----|----------------------|----------|
| `FEATURE_SCANNING_WIFI_ENABLED` | `int`/`boolean` | 0 | Предназначен для отладочных целей и должен быть удален из продакшн |

### 6.2. Настройка через build_flags

В `platformio.ini` можно переопределить настройки:

```ini
build_flags =
    -D WIFI_RECONNECT_ATTEMPTS=5
    -D WIFI_RECONNECT_INTERVAL_MS=5000
    -D WIFI_CONNECT_TIMEOUT_MS=15000
    -D FEATURE_SCANNING_WIFI_ENABLED=0
```

### 6.3. Заглушки

Если `TRANSPORT_TYPE != TRANSPORT_TYPE_WIFI`, все методы становятся пустыми, `STATE_WIFI_OK` никогда не устанавливается.

## 7. Требования к доработке

| # | Проблема | Приоритет | Решение |
|---|----------|-----------|---------|
| 1 | **AP-логика в wifi_manager** | 🔴 Критично | Вынести в `provisioning` |
| 2 | **Оркестратор отслеживает таймаут потери WiFi** | 🔴 Критично | Перенести логику в `wifi_manager` |
| 3 | **Отсутствуют константы переподключения** | 🔴 Критично | Добавить `WIFI_RECONNECT_ATTEMPTS`, `WIFI_RECONNECT_INTERVAL_MS`, `WIFI_CONNECT_TIMEOUT_MS` |
| 4 | **`WIFI_FALLBACK_TIMEOUT_MS` используется в оркестраторе** | 🔴 Критично | Перенести в `wifi_manager` |
| 5 | **Нет единого интерфейса `init()`/`update()`** | 🟡 Средний | Привести к единому стандарту слоёв |
