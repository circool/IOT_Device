# TRANSPORT_MATTER.md

## Matter-транспорт

---

## 1. Назначение

Matter — современный протокол умного дома, работающий поверх IP (WiFi, Thread). Обеспечивает унифицированное представление устройства и взаимодействие с экосистемами разных производителей (Apple Home, Google Home, Amazon Alexa и др.).

**Статус:** ⏳ Проектирование. Реализация отсутствует. Ожидает ESP-Matter SDK.

---

### 2.2. Поддерживаемые платформы

| Платформа | Поддержка Matter |
|-----------|------------------|
| ESP32-C6 | ✅ Да (WiFi + Thread) |
| ESP32-H2 | ✅ Да (Thread) |
| ESP32 (S3) | ⚠️ Частично (WiFi только, без Thread) |
| ESP8266 | ❌ Нет |

### 2.3. Отличия от MQTT и Zigbee

| Характеристика | MQTT | Zigbee | Matter |
|----------------|------|--------|--------|
| **Сеть** | Клиент-сервер | Ячеистая (mesh) | IP (WiFi/Thread) |
| **Адресация** | Топики | Endpoint+Cluster+Attr | Node+Endpoint+Cluster+Attr |
| **Публикация** | Периодическая | Отчёты | Подписки (Subscriptions) |
| **Команды** | Через топики | ZCL-команды | Matter-команды |
| **Multi-admin** | ❌ Нет | ❌ Нет | ✅ Да |
| **Commissioning** | Вручную | Через координатор | QR-код / числовой код |

## 3. Принцип представления

Устройство представляется как единый **Matter-узел (Node)**, содержащий несколько **конечных точек (Endpoints)** с типами устройств и кластерами, описанными в спецификации Matter.

Взаимодействие строится по модели:

```
{Node ID} → {Endpoint} → {Cluster} → {Attribute}
```

---

## 4. Типы устройств (Device Types)

Каждая конечная точка соответствует стандартизированному типу устройства:

| Endpoint | Device Type | ID | Применимость |
|----------|-------------|-----|--------------|
| **0** | Aggregator | 0x000E | Все типы (корневая точка) |
| **1** | Extended Color Light | 0x010D | TYPE 1, 3 |
| **2** | Temperature Sensor | 0x0302 | TYPE 1, 2 |
| **3** | Humidity Sensor | 0x0307 | TYPE 1, 2 |

**Примечание:** Extended Color Light используется вместо Fan, так как спецификация Matter на момент написания не включает отдельный тип для вентилятора. Управление скоростью реализуется через атрибут `CurrentLevel`.

## 5. Кластеры и атрибуты

### 5.1. Endpoint 0 — Aggregator (корневая точка)

| Кластер | ID | Назначение |
|---------|-----|------------|
| **Basic Information** | 0x0028 | `VendorName`, `ProductName`, `SoftwareVersion` |
| **OTA Software Update** | 0x002A | Обновление прошивки |
| **Custom (пользовательский)** | 0xFC00 | Пороги, таймеры, режимы |

**Пользовательский кластер (0xFC00) на Endpoint 0:**

| Атрибут | Тип | Назначение |
|---------|-----|------------|
| `SensorControlMode` | bool | Режим AUTO / MANUAL |
| `AdaptiveMode` | bool | Адаптивный режим |
| `LowTemp` | int16 | Нижний порог температуры (°C × 100) |
| `HighTemp` | int16 | Верхний порог температуры (°C × 100) |
| `LowHum` | uint16 | Нижний порог влажности (% × 100) |
| `HighHum` | uint16 | Верхний порог влажности (% × 100) |
| `DelaySeconds` | uint16 | Задержка включения (сек) |
| `MaxOnTime` | uint32 | Аварийное отключение (сек) |

### 5.2. Endpoint 1 — Extended Color Light (TYPE 1, 3)

| Кластер | ID | Обязательность | Атрибуты и команды |
|---------|-----|---------------|-------------------|
| **Identify** | 0x0003 | Обязательный | `Identify` — визуальная идентификация |
| **On/Off** | 0x0006 | Обязательный | `OnOff` — состояние; команды `On`, `Off`, `Toggle` |
| **Level Control** | 0x0008 | Обязательный | `CurrentLevel` — скорость (0-100%); команда `MoveToLevel` |
| **Groups** | 0x0004 | Обязательный | Групповое управление |

### 5.3. Endpoint 2 — Temperature Sensor (TYPE 1, 2)

| Кластер | ID | Обязательность | Атрибуты |
|---------|-----|---------------|----------|
| **Temperature Measurement** | 0x0402 | Обязательный | `MeasuredValue` — температура (°C × 100) |

### 5.4. Endpoint 3 — Humidity Sensor (TYPE 1, 2)

| Кластер | ID | Обязательность | Атрибуты |
|---------|-----|---------------|----------|
| **Relative Humidity Measurement** | 0x0405 | Обязательный | `MeasuredValue` — влажность (% × 100) |

### 5.5. Общие кластеры (все Endpoints)

| Кластер | ID | Назначение |
|---------|-----|------------|
| **Descriptor** | 0x001D | Идентификация типа устройства и состава конечной точки |

## 6. Типы взаимодействия

| Кластер | Публикация | Управление | Механизм |
|---------|-----------|------------|----------|
| **On/Off** | ✅ Да | ✅ Да | Подписка на атрибут `OnOff` + команды `On`/`Off` |
| **Level Control** | ✅ Да | ✅ Да | Подписка на `CurrentLevel` + команда `MoveToLevel` |
| **Temperature Measurement** | ✅ Да | ❌ Нет | Подписка на `MeasuredValue` |
| **Relative Humidity** | ✅ Да | ❌ Нет | Подписка на `MeasuredValue` |
| **Basic Information** | ✅ Да | ❌ Нет | Статические атрибуты |
| **OTA Software Update** | ❌ Нет | ✅ Да | Приём обновлений от контроллера |
| **Custom (0xFC00)** | ✅ Да | ✅ Да | Подписка на атрибуты + `WriteAttribute` |

## 7. Подписки (Subscriptions)

Matter использует модель **подписок** вместо периодической публикации:

1. Контроллер подписывается на атрибуты устройства
2. Устройство отправляет начальные значения при подписке
3. При изменении атрибута устройство отправляет обновление
4. Подписка поддерживается через регулярные keep-alive сообщения

**Особенности:**
- Подписки заменяют периодическую публикацию (как в MQTT)
- Не нужно настраивать интервалы отчётов (как в Zigbee)
- Контроллер сам определяет, на какие атрибуты подписываться

---

## 8. Commissioning (настройка)

Настройка выполняется через стандартную процедуру комиссионинга:

1. **QR-код** — сканируется приложением экосистемы
2. **Числовой код** — вводится вручную (11 цифр)
3. Устройство подключается к WiFi/Thread сети
4. Устройство регистрируется в экосистеме

**Интеграция с Provisioning:**

```
1. Пользователь сканирует QR-код на устройстве
2. Приложение передаёт WiFi/Thread credentials
3. Устройство подключается к сети
4. Устройство регистрируется в Matter-контроллере
5. Контроллер подписывается на атрибуты
```

## 9. Связь с MQTT и Zigbee (сравнение)

| Аспект | MQTT | Zigbee | Matter |
|--------|------|--------|--------|
| **Команда включения** | Топик + payload | ZCL-команда | Matter-команда |
| **Публикация состояния** | В топик | Отчёт атрибута | Обновление подписки |
| **Настройка порога** | Топик + payload | Write Attribute | Write Attribute |
| **Обновление прошивки** | Через Web (OTA) | Через OTA-кластер | Через OTA-кластер |
| **Multi-admin** | ❌ Нет | ❌ Нет | ✅ Да |
