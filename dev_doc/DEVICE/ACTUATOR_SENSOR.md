# ACTUATOR_SENSOR.md

## Исполнительные механизмы и датчик

## 1. Назначение

Документ описывает слои, работающие с железом:
- **Actuator** — управление физическими выходами (GPIO, ШИМ)
- **Sensor** — чтение физических показаний (температура, влажность)

## 2. Actuator — исполнительные механизмы

### 2.1. Общая архитектура

```
┌─────────────────────────────────────────────────────────────────┐
│                     ActuatorBase                               │
│  • Дискретное управление (ON/OFF)                             │
│  • Таймер отложенного включения (delaySeconds)                │
│  • Таймер аварийного отключения (maxOnTime → emergency)       │
│  • Колбэки: onSetPhysical, onForceStop, onManualCommand       │
└─────────────────────────────────────────────────────────────────┘
                              ▲
                              │
          ┌───────────────────┴───────────────────┐
          │                                       │
          ▼                                       ▼
┌─────────────────────────┐         ┌─────────────────────────┐
│      FanActuator        │         │    SwitchActuator       │
│  • ШИМ-управление       │         │  • Только ON/OFF        │
│  • Стартовый импульс    │         │  • Прокси-класс         │
│  • Флаг adaptiveMode    │         │    над ActuatorBase     │
└─────────────────────────┘         └─────────────────────────┘
```

### 2.2. ActuatorBase — базовый класс

**Назначение:** дискретное управление нагрузкой (ON/OFF) + таймеры.

**Ответственность:**
- Управление пином (HIGH/LOW)
- Таймер отложенного включения (`delaySeconds`)
- Таймер аварийного отключения (вычисляет `emergency`)

**Колбэки (указатели на функции, без virtual):**

| Колбэк | Сигнатура | Назначение |
|--------|-----------|------------|
| `onSetPhysicalCallback` | `void(*)(void*, bool)` | Вызов при изменении состояния пина |
| `onForceStopCallback` | `void(*)(void*)` | Вызов при аварийной остановке |
| `onManualCommandCallback` | `void(*)(void*)` | Вызов при ручной команде (manual=true) |

**Состояние (приватные поля):**

| Поле | Тип | Назначение |
|------|-----|------------|
| `_state` | bool | Текущее состояние (true=вкл) |
| `_startTime` | unsigned long | Время последнего включения (для maxOnTime) |
| `_delayActive` | bool | Активен ли таймер отложенного включения |
| `_delayTimer` | unsigned long | Время срабатывания таймера (millis) |
| `_emergencyStop` | bool | Аварийное отключение (вычисляется в checkMaxOnTime) |

**Публичные методы:**

| Метод | Назначение |
|-------|------------|
| `init(pin, relayOnLevel, bootState, delaySeconds, maxOnTime)` | Инициализация |
| `set(on, manual)` | Установить состояние (manual=true — ручная команда) |
| `getState()` | Получить состояние |
| `update(delaySeconds, maxOnTime)` | Периодический вызов в loop |
| `forceStop()` | Принудительное выключение (вызывает колбэк) |

### 2.3. FanActuator — вентилятор с ШИМ

**Назначение:** управление вентилятором с регулировкой скорости (TYPE 1).

**Ответственность:**
- ШИМ-управление (частота 500 Гц, разрешение 8 бит)
- Стартовый импульс (100% мощность на 200 мс для раскрутки)
- Хранение флага `adaptiveMode` (логика адаптации в оркестраторе)

**Дополнительные параметры:**

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `PWM_FREQUENCY` | 500 Гц | Частота ШИМ |
| `PWM_RESOLUTION` | 8 бит | Разрешение ШИМ |
| `PWM_STARTING` | 200 мс | Длина стартового импульса |
| `MIN_SPEED_PERCENT` | 10% | Минимальная скорость |

**Особенности:**
- При включении с `speed < 100%` — сначала подаётся 100% на 200 мс, затем снижается до заданной скорости
- При `speed = 0` — вентилятор выключается
- При `speed = 100%` — ШИМ отключается, используется дискретное управление

### 2.4. SwitchActuator — выключатель

**Назначение:** управление выключателем без ШИМ (TYPE 3).

**Ответственность:**
- Только ON/OFF (через `ActuatorBase`)
- Прокси-класс — все методы делегируются `ActuatorBase`

## 3. Sensor — датчик температуры/влажности

### 3.1. Поддерживаемые датчики

| Тип | Датчик | Интерфейс | Минимальный интервал |
|-----|--------|-----------|---------------------|
| `SENSOR_TYPE=1` | AHT10 | I2C | 100 мс |
| `SENSOR_TYPE=2` | DHT11 | 1-Wire | 1000 мс |
| `SENSOR_TYPE=2` | DHT22 | 1-Wire | 2000 мс |

### 3.2. API

> **Примечание:** В текущей реализации используется `sensor_update()` для единообразия синтаксиса. 

| Функция | Назначение |
|---------|------------|
| `sensor_init()` | Инициализация I2C/GPIO и первое чтение |
| `sensor_update()` / `sensor_loop()` | Чтение данных с соблюдением минимального интервала. Возвращает `true` если данные изменились |
| `sensor_getTemperature()` | Температура (°C) |
| `sensor_getHumidity()` | Влажность (%) |
| `sensor_isOk()` | Валидность данных |
| `sensor_getError()` | Текст ошибки |
| `sensor_getHumRate()` | Скорость изменения влажности (%/сек) |

### 3.3. Валидация данных

| Проверка | Действие |
|----------|----------|
| `isnan(temp)` или `isnan(hum)` | Ошибка, `sensorOk = false` |
| `hum < 0` или `hum > 100` | Ошибка, `sensorOk = false` |
| 3 последовательные ошибки чтения | `sensorOk = false` (для AHT10) |
| Восстановление после ошибок | `sensorOk = true`, ошибка очищается |

**Примечание:** Температура **не проверяется** на диапазон — бизнес-логика сама решает, что с ней делать.

### 3.4. Расчёт скорости изменения влажности

```cpp
_humRate = (hum - _lastHumValue) / dt;  // %/сек
```

- Положительное значение — влажность растёт
- Отрицательное — падает
- Ограничение: ±5 %/сек (фильтрация выбросов)

## 4. Связь с другими слоями

### 4.1. Actuator → DeviceController

Actuator **не знает** о DeviceController. Он предоставляет:
- Методы управления (`set()`, `setSpeed()`)
- Методы чтения состояния (`getState()`, `getSpeed()`, `isEmergencyStop()`)
- Колбэки для оркестратора

**Оркестратор** вызывает `Actuator::update()` в `loop()` и обрабатывает колбэки.

### 4.2. Sensor → DeviceController

Sensor **не знает** о DeviceController. Он предоставляет:
- Методы чтения (`sensor_getTemperature()`, `sensor_getHumidity()`, `sensor_isOk()`)

**DeviceController** вызывает `sensor_update()` и читает данные через геттеры.

### 4.3. Пример использования в оркестраторе

```cpp
// main.cpp — loop()
sensor_update();
fan->update();

if (sensor_isOk()) {
    float temp = sensor_getTemperature();
    float hum = sensor_getHumidity();
    // ... бизнес-логика ...
}

if (fan->isEmergencyStop()) {
    system_state_set_bit(STATE_EMERGENCY);
}
```

## 5. Флаги компиляции

### 5.1. Actuator

| Флаг | По умолчанию | Описание |
|------|--------------|----------|
| `SWITCH_PIN` | 14 (ESP8266) / 4 (ESP32) | Пин управления реле |
| `RELAY_ON_LEVEL` | LOW | Уровень включения реле |
| `PWM_ENABLED` | 1 | Включить ШИМ (для TYPE 1) |
| `PWM_FREQUENCY` | 500 | Частота ШИМ (Гц) |
| `PWM_RESOLUTION` | 8 | Разрешение ШИМ (бит) |
| `PWM_STARTING` | 200 | Длина стартового импульса (мс) |

### 5.2. Sensor

| Флаг | По умолчанию | Описание |
|------|--------------|----------|
| `SENSOR_TYPE` | 1 | 1 = AHT10, 2 = DHT |
| `I2C_SDA_PIN` | 4 (ESP8266) / 21 (ESP32) | SDA для AHT10 |
| `I2C_SCL_PIN` | 5 (ESP8266) / 22 (ESP32) | SCL для AHT10 |
| `SENSOR_PIN` | 4 (ESP8266) / 16 (ESP32) | Пин для DHT |
| `DHT_TYPE` | DHT22 | DHT11 или DHT22 |
| `SENSOR_INTERVAL_MIN` | 1 | Минимальный интервал опроса (сек) |
| `SENSOR_INTERVAL_MAX` | 50 | Максимальный интервал опроса (сек) |
