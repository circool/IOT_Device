# OTA_MANAGER.md

## Обновление прошивки по воздуху (OTA)

---

## 1. Назначение

OTA (Over-The-Air) — механизм обновления прошивки устройства без физического подключения через USB. Позволяет устанавливать новые версии прошивки через веб-интерфейс.

---

## 2. Доступность

OTA доступен **только** на устройствах с Flash-памятью ≥ 2 МБ.

| Условие | OTA доступен |
|---------|--------------|
| Flash < 2MB | ❌ НЕТ |
| Flash ≥ 2MB | ✅ ДА |

**Проверка:** `ota_is_available()` возвращает `true` только если Flash ≥ 2MB и достаточно свободного места.

## 4. API

| Функция | Назначение |
|---------|------------|
| `ota_init(server)` | Инициализация OTA (регистрация маршрута `/update` через ElegantOTA) |
| `ota_is_available()` | Проверка доступности (Flash ≥ 2MB). Если OTA выключена на этапе компиляции — заглушка возвращает `false`. |
| `ota_loop()` | Обработка OTA-запроса в цикле (ElegantOTA работает через `server.handleClient()`) |

---

## 5. Интеграция с Web

### 5.1. Маршрут `/update`

Маршрут `/update` регистрируется OTA-слоем через `ElegantOTA.begin(server)`. Это **исключение** из-за использования сторонней библиотеки.

```cpp
void ota_init(WebServerClass* server) {
    if (!ota_is_available()) return;
    ElegantOTA.begin(server);
}
```

### 5.2. Кнопка OTA в Web

Web-слой **не знает** о `FEATURE_OTA_ENABLED`. Кнопка OTA отображается на основе вызова `ota_is_available()`:

```cpp
// html_templates.h
if (ota_is_available()) {
    send(F("<a href='/update' class='link-btn'>Upgrade firmware (OTA)</a>"), context);
}
```

**Принцип:** OTA-слой предоставляет заглушку `ota_is_available()`, которая возвращает `false`, если OTA выключена на этапе компиляции. Web-слой вызывает функцию без `#ifdef`.

---

## 6. Процесс обновления

```
1. Пользователь открывает страницу /update
2. Выбирает файл прошивки (.bin)
3. Нажимает кнопку загрузки
4. ElegantOTA загружает файл
5. Отображается прогресс
6. После успешной загрузки — автоматическая перезагрузка
7. Устройство загружается с новой прошивкой
```

**Особенности:**
- При ошибке (обрыв соединения, недостаточно места) — отображается сообщение
- Вся обработка ошибок — внутри ElegantOTA

---

## 7. Исключение: OTA-слой знает о WebServer

OTA-слой принимает `WebServerClass*` и вызывает `ElegantOTA.begin(server)`, потому что библиотека ElegantOTA сама регистрирует HTTP-маршрут `/update`. Это **единственное** место, где OTA-слой знает о Web-сервере.

**Границы исключения:**
- OTA-слой НЕ генерирует HTML (кнопка — в Web)
- OTA-слой НЕ знает о CSS-классах
- OTA-слой только: `init(server)`, `isAvailable()`, `loop()`

---

## 8. Флаги компиляции

| Флаг | По умолчанию | Описание |
|------|--------------|----------|
| `FEATURE_OTA_ENABLED` | 1 | Включить OTA-обновления |

**Заглушки при выключенной OTA:**

```cpp
// ota.h
#if FEATURE_OTA_ENABLED == 1
    bool ota_is_available();
    void ota_init(WebServerClass* server);
    void ota_loop();
#else
    inline bool ota_is_available() { return false; }
    inline void ota_init(WebServerClass* server) { (void)server; }
    inline void ota_loop() {}
#endif
```

---

## 9. Требования к железу

- Flash-память ≥ 2MB
- Достаточно свободного места для загрузки новой прошивки (проверяется в `ota_is_available()`)

## 10. Связь с другими слоями

| Слой | Как используется OTA |
|------|---------------------|
| **Web** | Вызывает `ota_is_available()` для отображения кнопки; маршрут `/update` регистрируется OTA-слоем |
| **Оркестратор** | Вызывает `ota_init(server)` и `ota_loop()` |
| **ConfigManager** | Не знает об OTA |
