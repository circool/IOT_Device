## 1. Назначение

Слой `ButtonManager` обеспечивает обработку механической кнопки с определением стадий удержания. Слой инкапсулирует чтение GPIO, антидребезг (алгоритмический, за счёт больших временных интервалов) и детектирование фронтов. Результат обработки предоставляется оркестратору через метод опроса `getStage()`.

Слой не содержит логики принятия решений.

## 3. API

### 3.1. init()

```cpp
void init();
```

**Назначение:** инициализация пина кнопки и сброс внутреннего состояния.

**Параметры:** отсутствуют (используются константы `BUTTON_PIN`, `BUTTON_INVERTED`).

**Возвращаемое значение:** отсутствует.

---

### 3.2. update()

```cpp
void update();
```

**Назначение:** обновление состояния кнопки. Вызывается в `loop()`.

**Параметры:** отсутствуют.

**Возвращаемое значение:** отсутствует.

**Поведение:**
- Читает состояние пина с учётом инверсии
- Детектирует фронты (нажатие / отпускание)
- Подсчитывает длительность удержания
- Обновляет внутреннюю стадию

---

### 3.3. getStage()

```cpp
ButtonStage getStage() const;
```

**Назначение:** получить текущую стадию нажатия.

**Параметры:** отсутствуют.

**Возвращаемое значение:** `ButtonStage`:
- `BUTTON_IDLE` — кнопка не нажата или удержание > 5 с
- `BUTTON_SHORT` — нажатие < 0,5 с (событие после отпускания)
- `BUTTON_MID` — удержание 1–2 с (активное состояние)
- `BUTTON_LONG` — удержание 2–3 с (активное состояние)
- `BUTTON_WARN` — удержание 3–5 с (активное состояние, предупреждение)
- `BUTTON_HOLD` — удержание 4–5 с и отпущена (событие, сброс)

---

### 3.4. clearEvent()

```cpp
void clearEvent();
```

**Назначение:** принудительный сброс событийных стадий (`BUTTON_SHORT`, `BUTTON_HOLD`) в `BUTTON_IDLE`.

**Параметры:** отсутствуют.

**Возвращаемое значение:** отсутствует.

**Поведение:**
- Если текущая стадия равна `BUTTON_SHORT` или `BUTTON_HOLD` — сбрасывает её в `BUTTON_IDLE`
- В остальных случаях ничего не делает
- Логирует сброс на уровне `DEBUG`

**Применение:** используется оркестратором для однократной обработки событий, когда стадию необходимо сбросить сразу после реакции, не дожидаясь следующего цикла `update()`.

**Важно:** сброс применяется только к **событийным стадиям** (`BUTTON_SHORT`, `BUTTON_HOLD`). Стадии-состояния (`BUTTON_MID`, `BUTTON_LONG`, `BUTTON_WARN`) не сбрасываются, так как отражают текущее удержание кнопки.

**Пример использования:**

```cpp
void loop() {
    g_buttonManager.update();
    
    ButtonStage stage = g_buttonManager.getStage();
    
    if (stage == BUTTON_SHORT) {
        XLOG_INFO(CAT_MAIN, "Short press — toggling actuator");
        deviceController.toggle();
        g_buttonManager.clearEvent();  // ← Сброс после обработки
    }
    
    if (stage == BUTTON_HOLD) {
        XLOG_WARN(CAT_MAIN, "Factory reset triggered!");
        g_configManager.reset(g_transportConfig);
        restartRequest(500);
        g_buttonManager.clearEvent();  // ← Сброс после обработки
    }
}
```

## 4. Стадии нажатия

| Стадия | Интервал | Тип | Описание |
|--------|----------|-----|----------|
| `BUTTON_IDLE` | — | Состояние | Кнопка не нажата или удержание > 5 с |
| `BUTTON_SHORT` | < 0,5 с | **Событие** | Короткое нажатие (после отпускания). Сбрасывается вызовом `clearEvent()` или следующим `update()` |
| `BUTTON_MID` | 1–2 с | Состояние | Удержание, активная стадия |
| `BUTTON_LONG` | 2–3 с | Состояние | Удержание, активная стадия |
| `BUTTON_WARN` | 3–5 с | Состояние | Предупреждение о скором сбросе |
| `BUTTON_HOLD` | 4–5 с | **Событие** | Сброс (после отпускания). Сбрасывается вызовом `clearEvent()` или следующим `update()` |

**Важно:** `BUTTON_SHORT` и `BUTTON_HOLD` являются **событиями** и устанавливаются **только при отпускании** кнопки. Для предотвращения повторной обработки рекомендуется вызывать `clearEvent()` после реакции на событие.

## 5. Интеграция с оркестратором

```cpp
void loop() {
    g_buttonManager.update();
    
    ButtonStage stage = g_buttonManager.getStage();
    
    // Обработка событий с очисткой
    if (stage == BUTTON_SHORT) {
        XLOG_INFO(CAT_MAIN, "Short press — toggling actuator");
        deviceController.toggle();
        g_buttonManager.clearEvent();
    }
    
    if (stage == BUTTON_HOLD) {
        XLOG_WARN(CAT_MAIN, "Factory reset triggered!");
        g_configManager.reset(g_transportConfig);
        restartRequest(500);
        g_buttonManager.clearEvent();
    }
    
    // LED-индикация (стадии-состояния)
    if (stage == BUTTON_IDLE) {
        update_led_from_status();
    } else {
        update_led_from_button(stage);
    }
    
    led_update();
    restartUpdate();
}
```

**Примечание:** оркестратор принимает решения на основе полученной стадии. Слой `ButtonManager` не содержит логики принятия решений. Для событийных стадий рекомендуется вызывать `clearEvent()` после обработки во избежание повторных срабатываний.

## 6. Настройка

| Флаг | По умолчанию | Описание |
|------|--------------|----------|
| `FEATURE_BUTTON_ENABLED` | — | Пользовательский флаг включения слоя (`-D FEATURE_BUTTON_ENABLED=1`) |
| `BUTTON_PIN` | `0` | Номер GPIO |
| `BUTTON_INVERTED` | `1` | `1` = LOW активен (подтяжка к GND) |

Внутренний флаг `USE_BUTTON` определяется в `settings.h` на основе `FEATURE_BUTTON_ENABLED`. При отключении слоя все методы становятся пустыми заглушками, `getStage()` возвращает `BUTTON_IDLE`.

**Пример включения:**
```ini
build_flags =
    -D FEATURE_BUTTON_ENABLED=1
    -D BUTTON_PIN=4
```
