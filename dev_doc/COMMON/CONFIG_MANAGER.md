## 1. Назначение

`ConfigManager` — слой абстракции над энергонезависимой памятью (EEPROM), обеспечивающий сохранение, загрузку и валидацию конфигурационных данных. Предоставляет единый механизм доступа к настройкам для всех компонентов системы.

Слой является критическим: без его функционирования невозможна инициализация `DeviceController` (отсутствуют `DeviceConfig`) и транспортного слоя (отсутствует `TransportConfig`).

## 2. Архитектурное место

```
┌─────────────────────────────────────────────────────────────────────┐
│                              ОРКЕСТРАТОР                            │
│                                                                     │
│  • Инициализирует ConfigManager                                     │
│  • Загружает конфигурацию через get()                               │
│  • Сохраняет конфигурацию через set()                               │
│  • Сбрасывает конфигурацию через reset()                            │
└─────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────┐
│                              CONFIG MANAGER                         │
│                                                                     │
│  • Чтение/запись EEPROM                                             │
│  • Хранение TransportConfig и DeviceConfig                          │
│  • Проверка целостности (магическое число, CRC)                     │
│  • Валидация данных (границы, обязательные поля)                    │
│  • Раздельное хранение конфигурационных блоков                      │
└─────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────┐
│                              EEPROM                                 │
└─────────────────────────────────────────────────────────────────────┘
```

**Потоки данных:**
- `ConfigManager → Оркестратор`: предоставление загруженных настроек
- `Оркестратор → ConfigManager`: сохранение изменённых настроек
- `Оркестратор → ConfigManager`: сброс настроек к значениям по умолчанию
- `DeviceController` и транспорт получают настройки через оркестратора (косвенная зависимость)

## 3. Ответственность

| Ответственность | Описание |
|-----------------|----------|
| **Загрузка конфигурации** | Чтение данных из EEPROM при инициализации |
| **Сохранение конфигурации** | Запись данных в EEPROM при изменении |
| **Сброс конфигурации** | Запись значений по умолчанию в EEPROM |
| **Проверка целостности** | Проверка магического числа и контрольной суммы |
| **Валидация данных** | Проверка границ допустимых значений и обязательных полей |
| **Раздельное хранение** | Независимое управление `TransportConfig` и `DeviceConfig` |
| **Предоставление доступа** | Геттеры и сеттеры для структур конфигурации |

### 3.1. Геттеры

#### 3.1.1. Алгоритм работы

1. Читает MAGIC и блок данных (CRC + данные) из энергонезависимой памяти'.
   - При ошибке чтения — возвращает `false`.
2. Проверяет целостность прочитанных данных:
   - Соответствие MAGIC ожидаемому значению
   - Соответствие сохранённой CRC вычисленной
   - При ошибке возвращает `false`
3. Проверяет семантическую корректность каждого поля:
   - Числовые значения — в допустимых диапазонах
   - Строковые значения — допустимая длина и набор символов
   - Обязательные поля — не пустые (где требуется)
   - При ошибке возвращает `false`

4. Заполняет переданную по ссылке структуру
5. Возвращает результат:
   - `true` — если **все** проверки (MAGIC, CRC, семантика) пройдены успешно
   - `false` — если хотя бы одна проверка не пройдена (даже если поля исправлены)

#### 3.1.2. Права

- **Имеет право** изменять содержимое полей структуры, переданной по ссылке (исправлять невалидные поля)
- **Не имеет права** изменять содержимое энергонезависимой памяти

---

### 3.2. Сеттеры

#### 3.2.1. Алгоритм работы

1. Проверяет семантическую корректность каждого поля переданной структуры:
   - Числовые значения — в допустимых диапазонах
   - Строковые значения — допустимая длина и набор символов
   - Обязательные поля — не пустые (где требуется)
   - При наличии невалидных полей — немедленно возвращает `false`, не изменяя энергонезависимую память и не выполняя дальнейших действий

2. Читает текущие данные из памяти (без CRC).
   - При ошибке чтения — считает, что данных нет, и переходит к записи

3. Сравнивает полученные данные с прочитанными.
   - Если данные идентичны — немедленно возвращает `true`, не изменяя энергонезависимую память и не выполняя дальнейших действий

4. Формирует блок для записи:
   - Вычисляет CRC от данных
   - Формирует блок: CRC + данные

5. Записывает блок в энергонезависимую память.

6. Проверяет MAGIC:
   - Если MAGIC отсутствует или невалиден — записывает актуальное значение

7. Возвращает результат:
   - `true` — если запись выполнена успешно
   - `false` — если запись не удалась

#### 3.2.2. Права

- **Имеет право** изменять содержимое энергонезависимой памяти
- **Не имеет права** изменять содержимое структуры, переданной по ссылке (только читает)
- **Имеет право** пропускать запись, если данные не изменились

---

### 3.3. Сброс (Resetters)

#### 3.3.1. Алгоритм работы

1. Заполняет переданную структуру значениями по умолчанию

2. Проверяет на совпадение CRC
  - при совпадении ничего не делает
  - при несовпадении - записывает данные в энергонезависимую память


#### 3.3.2. Права

- **Имеет право** изменять содержимое полей структуры, переданной по ссылке
- **Имеет право** изменять содержимое энергонезависимой памяти

## 4. Структуры данных

`ConfigManager` оперирует двумя структурами, определёнными в `common_types.h`:

### 4.1. TransportConfig

Параметры канала связи, состав которых зависит от флагов компиляции:

```cpp
typedef struct {
    char deviceId[32];
    
    #ifdef USE_WIFI
        char wifiSsid[32];
        char wifiPassword[64];
    #endif
    
    #ifdef USE_MQTT
        char mqttBroker[64];
        uint16_t mqttPort;
        char mqttUser[32];
        char mqttPassword[64];
        char mqttClientId[24];
    #endif
    
    #ifdef USE_ZIGBEE
        uint16_t zigbeePanId;
        uint8_t zigbeeChannel;
        char zigbeeNetworkKey[32];
    #endif
} TransportConfig;
```

### 4.2. DeviceConfig

Параметры работы устройства, состав которых зависит от `DEVICE_TYPE`:

```cpp
typedef struct {
    #if DEVICE_TYPE == 1
        bool sensorControlMode;
        bool adaptiveMode;
        float lowTemp;
        float highTemp;
        float lowHum;
        float highHum;
        uint8_t speedPercent;
    #endif
    
    #if DEVICE_TYPE == 1 || DEVICE_TYPE == 3
        uint32_t delaySeconds;
        uint32_t maxOnTime;
        bool bootState;
    #endif
} DeviceConfig;
```

## 5. Интерфейс

Публичный интерфейс слоя:

```cpp
class ConfigManager {
public:
    /**
     * @brief Инициализация менеджера конфигурации
     * @return true при успешной инициализации, false при ошибке
     */
    bool init();
    
    /**
     * @brief Сохранение конфигурации транспорта
     * @param config Структура с параметрами транспорта
     * @return true при успешной записи, false при ошибке
     */
    bool set(const TransportConfig& config);
    
    /**
     * @brief Загрузка конфигурации транспорта
     * @param config Ссылка на структуру для заполнения
     * @return true при успешном чтении, false при ошибке
     * @note Выполняет полную валидацию данных: CRC и семантическую проверку
     *         Невалидные значения заполняются пусто/ноль/ложь
     */
    bool get(TransportConfig& config);
    
    /**
     * @brief Сохранение настроек устройства
     * @param settings Структура с настройками устройства
     * @return true при успешной записи, false при ошибке
     */
    bool set(const DeviceConfig& settings);
    
    /**
     * @brief Загрузка настроек устройства
     * @param settings Ссылка на структуру для заполнения
     * @return true при успешном чтении, false при ошибке
     * @note Выполняет полную валидацию данных: CRC и семантическую проверку
     *         Невалидные значения заполняются пусто/ноль/ложь
     */
    bool get(DeviceConfig& settings);
    
    /**
     * @brief Сброс конфигурации транспорта к значениям по умолчанию
     * @param config Ссылка на структуру для заполнения значениями по умолчанию
     */
    void reset(TransportConfig& config);
    
    /**
     * @brief Сброс настроек устройства к значениям по умолчанию
     * @param settings Ссылка на структуру для заполнения значениями по умолчанию
     */
    void reset(DeviceConfig& settings);
};
```

**Важно:** Для разных платформ используются разные подходы
- ESP8266 использует библиотеку EEPROM
- ESP32 использует Preferences

## 6. Внутренние методы

Реализация слоя содержит приватные методы для обеспечения целостности и валидности данных:

### 6.1. calculateCRC

Вычисление контрольной суммы для проверки целостности данных.

```cpp
/**
 * @brief Вычисление 16-битной контрольной суммы CRC
 * @param data Указатель на данные
 * @param len Размер данных в байтах
 * @return 16-битное значение CRC
 */
static uint16_t calculateCRC(const uint8_t* data, size_t len);
```

**Алгоритм:** CRC-16 с полиномом 0x8005 (CRC-16/IBM). Начальное значение — 0x0000.

### 6.2. validateTransportConfig

Проверка семантической корректности конфигурации транспорта.

```cpp
/**
 * @brief Валидация конфигурации транспорта
 * @param config Структура для проверки
 * @return true если все поля валидны, иначе false
 */
bool validateTransportConfig(TransportConfig& config) const;
```

**Проверки:**
- `deviceId` не пуст и соответствует маске (буквы, цифры, подчёркивание), длина в допустимых границах
- `wifiSsid` не пуст (если USE_WIFI определён), длина в допустимых границах
- `wifiPassword` длина в допустимых границах (может быть пустым)
- `mqttBroker` не пуст (если USE_MQTT определён)
- `mqttPort` в допустимом диапазоне
- `mqttClientId` не пуст
- `zigbeePanId` в допустимом диапазоне (если USE_ZIGBEE определён)
- `zigbeeChannel` в допустимом диапазоне

### 6.3. validateDeviceConfig

Проверка семантической корректности настроек устройства.

```cpp
/**
 * @brief Валидация настроек устройства
 * @param settings Структура для проверки
 * @return true если все поля валидны, иначе false
 */
bool validateDeviceConfig(DeviceConfig& settings) const;
```

**Проверки (для DEVICE_TYPE == 1):**
- `lowTemp` < `highTemp`, оба в допустимом диапазоне
- `lowHum` < `highHum`, оба в допустимом диапазоне
- `speedPercent` в допустимом диапазоне (0-100)

**Проверки (для DEVICE_TYPE == 1 || DEVICE_TYPE == 3):**
- `delaySeconds` в допустимом диапазоне
- `maxOnTime` в допустимом диапазоне (0 — отключено)

### 6.4. checkMagic

Проверка магического числа.

```cpp
/**
 * @brief Проверка магического числа в EEPROM
 * @param offset Смещение блока в EEPROM
 * @return true если MAGIC совпадает, false в противном случае
 */
bool checkMagic(size_t offset) const;
```

**Назначение:** MAGIC — метка для разработчика. При обновлении прошивки, когда требуется имитировать невалидный конфиг, разработчик изменяет значение MAGIC в директивах компиляции. При этом сами настройки остаются в тех же ячейках памяти, но система считает их невалидными. Это позволяет избежать повторного конфигурирования при отладке.

### 6.5 read

Чтение без проверки

```cpp
/**
* @brief Чтение данных из EEPROM без валидации
* @param config Структура для заполнения
* @return true при успешном чтении, false при ошибке
*/
bool read(TransportConfig& config) const;
bool read(DeviceConfig& settings) const;
```

## 7. Жизненный цикл

### 7.1. Инициализация

1. Вызов `init()` при старте системы
2. Инициализация энергонезависимой памяти (выделение памяти, подготовка к чтению/записи)


### 7.2. Загрузка

1. Вызов `get()` с передачей структуры для заполнения
2. Чтение данных из энергонезависимой памяти
3. Проверка магического числа (если определено)
4. При несовпадении MAGIC — переход к п.8
5. Проверка контрольной суммы
6. При невалидности CRC — переход к п.8
7. Заполнение полей полученной структуры и возврат `true`
8. Возврат `false`


### 7.3. Сохранение

1. Вызов `set()` с переданной структурой
2. Семантическая валидация данных через `validate*()`
3. При невалидности — возврат `false`
4. Чтение текущих данных из энергонезависимой памяти
5. Сравнение с сохраняемыми данными (побайтово)
6. При полном совпадении — возврат `true` без записи
7. При различии — запись нового блока с пересчётом CRC
8. Запись магического числа (если отличается)

**Принцип:** реальная запись выполняется только при наличии изменений. Это минимизирует количество циклов записи в EEPROM и увеличивает срок службы памяти.

### 7.4. Сброс

1. Вызов `reset()` с передачей структуры для заполнения
2. Заполнение структуры значениями из макросов `DEFAULT_*`
3. Запись структуры в EEPROM через `write()`
4. Возврат результата выполнения `write()`

**Макросы DEFAULT_* определены в `settings.h` и могут быть переопределены в `credentials.h`:**

**TransportConfig:**
- `DEFAULT_DEVICE_ID` → "device"
- `DEFAULT_WIFI_SSID` → "" (если USE_WIFI)
- `DEFAULT_WIFI_PASSWORD` → "" (если USE_WIFI)
- `DEFAULT_MQTT_BROKER` → "" (если USE_MQTT)
- `DEFAULT_MQTT_PORT` → 1883 (если USE_MQTT)
- `DEFAULT_MQTT_USER` → "" (если USE_MQTT)
- `DEFAULT_MQTT_PASSWORD` → "" (если USE_MQTT)
- `DEFAULT_MQTT_CLIENT_ID` → "client" (если USE_MQTT)
- `DEFAULT_ZIGBEE_PAN_ID` → 0x0000 (если USE_ZIGBEE)
- `DEFAULT_ZIGBEE_CHANNEL` → 11 (если USE_ZIGBEE)

**DeviceConfig (для DEVICE_TYPE == 1):**
- `DEFAULT_SENSOR_CONTROL_MODE` → true
- `DEFAULT_ADAPTIVE_MODE` → false
- `DEFAULT_LOW_TEMP` → 26.0
- `DEFAULT_HIGH_TEMP` → 30.0
- `DEFAULT_LOW_HUM` → 50.0
- `DEFAULT_HIGH_HUM` → 65.0
- `DEFAULT_SPEED_PERCENT` → 50

**DeviceConfig (для DEVICE_TYPE == 1 || DEVICE_TYPE == 3):**
- `DEFAULT_DELAY_SECONDS` → 0
- `DEFAULT_MAX_ON_TIME` → 3600
- `DEFAULT_BOOT_STATE` → false

## 8. Формат хранения

Энергонезваисимая память содержит единое магическое число и два независимых конфигурационных блока:

```
┌─────────────────────────────────────────────────────────────┐
│ MAGIC (uint16_t) = 0x5A5                                    │
├─────────────────────────────────────────────────────────────┤
│ БЛОК ТРАНСПОРТА                                             │
│  ┌────────────────────────────────────────────────────────┐ │
│  │ CRC (uint16_t) = контрольная сумма данных блока        │ │
│  │ Данные (sizeof(TransportConfig))                       │ │
│  └────────────────────────────────────────────────────────┘ │
├─────────────────────────────────────────────────────────────┤
│ БЛОК УСТРОЙСТВА                                             │
│  ┌────────────────────────────────────────────────────────┐ │
│  │ CRC (uint16_t) = контрольная сумма данных блока        │ │
│  │ Данные (sizeof(DeviceConfig))                          │ │
│  └────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

**Смещения в EEPROM:**
- `MAGIC_OFFSET` = 0x0000
- `TRANSPORT_OFFSET` = (2)
- `DEVICE_OFFSET` = `TRANSPORT_OFFSET` + `sizeof(TransportConfig)` + 2

## 9. Константы валидации

Для семантической проверки данных определены следующие константы (в `settings.h`):

### 9.1. Общие константы

| Константа | Значение | Назначение |
|-----------|----------|------------|
| `DEVICE_ID_MIN_LEN` | 1 | Минимальная длина идентификатора устройства |
| `DEVICE_ID_MAX_LEN` | 31 | Максимальная длина идентификатора устройства |

### 9.2. Константы WiFi (USE_WIFI)

| Константа | Значение | Назначение |
|-----------|----------|------------|
| `WIFI_SSID_MIN_LEN` | 1 | Минимальная длина SSID |
| `WIFI_SSID_MAX_LEN` | 31 | Максимальная длина SSID |
| `WIFI_PASSWORD_MAX_LEN` | 63 | Максимальная длина пароля (0 — допустимо) |

### 9.3. Константы MQTT (USE_MQTT)

| Константа | Значение | Назначение |
|-----------|----------|------------|
| `MQTT_BROKER_MIN_LEN` | 1 | Минимальная длина адреса брокера |
| `MQTT_BROKER_MAX_LEN` | 63 | Максимальная длина адреса брокера |
| `MQTT_PORT_MIN` | 1 | Минимальный порт MQTT |
| `MQTT_PORT_MAX` | 65535 | Максимальный порт MQTT |
| `MQTT_CLIENT_ID_MIN_LEN` | 1 | Минимальная длина Client ID |
| `MQTT_CLIENT_ID_MAX_LEN` | 23 | Максимальная длина Client ID |

### 9.4. Константы ZigBee (USE_ZIGBEE)

| Константа | Значение | Назначение |
|-----------|----------|------------|
| `ZIGBEE_PAN_ID_MIN` | 0x0000 | Минимальный PAN ID |
| `ZIGBEE_PAN_ID_MAX` | 0xFFFF | Максимальный PAN ID |
| `ZIGBEE_CHANNEL_MIN` | 11 | Минимальный канал ZigBee |
| `ZIGBEE_CHANNEL_MAX` | 26 | Максимальный канал ZigBee |

### 9.5. Константы устройства (DEVICE_TYPE == 1)

| Константа | Значение | Назначение |
|-----------|----------|------------|
| `LOW_TEMP_MIN` | -40.0 | Минимальная нижняя граница температуры, °C |
| `LOW_TEMP_MAX` | 60.0 | Максимальная нижняя граница температуры, °C |
