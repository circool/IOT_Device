# TRANSPORT_WEB.md

## Web-транспорт

---

## 1. Назначение

Web — синхронный транспорт, обеспечивающий:

- Отображение состояния устройства (страница `/`)
- Настройку параметров (страница `/config`, форма `/save`)
- Оперативное управление (команды через `/set`)
- OTA-обновление прошивки (страница `/update`)

**В отличие от MQTT/Zigbee, Web не реализует структуру `Transport`, потому что:**

| Характеристика | MQTT/Zigbee | Web (HTTP) |
|----------------|-------------|------------|
| **Тип** | Асинхронный (подписка/публикация) | Синхронный (запрос/ответ) |
| **Команды** | Через колбэки | Через HTTP-запросы |
| **Данные** | Публикуются в топики | Отображаются на страницах |
| **Интерфейс** | `Transport` | `IWebStatusProvider` + флаги |

## 2. Реализация

### 2.1. Файлы

| Файл | Назначение |
|------|------------|
| `web_manager.h/cpp` | HTTP-сервер, маршруты, обработчики |
| `html_templates.h` | HTML-шаблоны в PROGMEM |

### 2.2. Зависимости

| Платформа | Библиотека |
|-----------|------------|
| ESP8266 | `ESP8266WebServer` |
| ESP32 | `WebServer` |

### 2.3. Особенности реализации

| Особенность | Описание |
|-------------|----------|
| **Chunked transfer** | Для экономии RAM страницы отправляются по частям |
| **PROGMEM** | HTML-шаблоны хранятся во Flash |
| **Буферизация (ESP32)** | Накопление до 1024 байт перед отправкой |
| **Прямая отправка (ESP8266)** | Без буферизации (экономия RAM) |

## 3. IWebStatusProvider

### 3.1. Назначение

Абстракция для получения данных устройства Web-слоем. Оркестратор реализует этот интерфейс и регистрирует его через `web_registerStatusProvider()`.

### 3.2. Интерфейс

```cpp
class IWebStatusProvider {
public:
    virtual ~IWebStatusProvider() = default;

    // Основная информация (TYPE 1 и 3)
    virtual bool isDeviceOn() const = 0;
    virtual bool isEmergencyStop() const = 0;
    virtual bool isDelayActive() const = 0;
    virtual unsigned long getDelayTimer() const = 0;
    virtual unsigned long getStartTime() const = 0;

    // Вентилятор (только TYPE 1)
    virtual int getSpeedPercent() const = 0;
    virtual bool isAdaptiveModeActive() const = 0;

    // Датчик (TYPE 1 и 2)
    virtual bool isSensorOk() const = 0;
    virtual float getTemperature() const = 0;
    virtual float getHumidity() const = 0;
    virtual const char* getSensorError() const = 0;

    // Подключения (все типы)
    virtual bool isMqttConnected() const = 0;
    virtual int getWifiRssi() const = 0;
};
```

### 3.3. Реализации

| Класс | Тип устройства | Описание |
|-------|----------------|----------|
| `FanWebStatusProvider` | TYPE 1 | Вентилятор с датчиком |
| `SensorWebStatusProvider` | TYPE 2 | Автономный датчик (актуатор — заглушки) |
| `SwitchWebStatusProvider` | TYPE 3 | Управляемый выключатель (датчик — заглушки) |

### 3.4. Регистрация

```cpp
// В оркестраторе (main.cpp)
static FanWebStatusProvider statusProvider(&fanActuator, &mqttManager);
web_registerStatusProvider(&statusProvider);
```

## 4. Маршруты

| URL | Метод | Назначение |
|-----|-------|------------|
| `/` | GET | Страница состояния (или редирект на `/config` если `FEATURE_WEB_STATUS_ENABLED == 0`) |
| `/config` | GET | Страница настройки параметров |
| `/save` | POST | Сохранение конфигурации |
| `/update` | GET/POST | OTA-обновление (регистрируется OTA-слоем через ElegantOTA) |
| `/set` | GET | Оперативная команда (см. раздел 6) |
| `/resetall` | GET | Сброс настроек (опционально) |
| `/savewifi` | POST | Сохранение WiFi при провизионинге (AP-режим) |

## 5. Команды от Web к оркестратору

### 5.1. Механизм

Web **не вызывает** `config_save()` и `ESP.restart()` напрямую. Вместо этого он устанавливает флаги, которые оркестратор читает в `loop()`.

### 5.2. Флаги

```cpp
// web_manager.h
extern volatile bool g_webConfigPending;   // Флаг: есть новые настройки
extern volatile bool g_webRestartPending;  // Флаг: запрошена перезагрузка
extern ConfigData g_webPendingConfig;      // Буфер с новыми настройками
```

### 5.3. Поток сохранения конфигурации

```
1. Пользователь заполняет форму на /config и нажимает Save
2. Web::web_saveConfig():
   a. Копирует текущую конфигурацию как базу
   b. Парсит все параметры из формы
   c. Валидирует каждый параметр
   d. Устанавливает g_webConfigPending = true
   e. Показывает страницу успеха
3. Оркестратор в loop() видит g_webConfigPending:
   a. Вызывает config_save(&g_webPendingConfig)
   b. Сбрасывает g_webConfigPending = false
   c. Вызывает restart_request(1000)
4. RestartManager перезагружает устройство
```

### 5.4. Поток оперативной команды (через `/set`)

```
1. Пользователь отправляет GET-запрос: /set?state=ON
2. Web обрабатывает запрос:
   a. Устанавливает команду во внутренний буфер
   b. Показывает страницу успеха
3. Оркестратор в loop() видит новую команду:
   a. Вызывает DeviceController::setState(true)
   b. Очищает буфер команды
```

## 6. Оперативные команды (через `/set`)

| Параметр | Тип | Значения | Применимость |
|----------|-----|----------|--------------|
| `state` | bool | `on` / `off` | TYPE 1, 3 |
| `speed` | uint8_t | 0-100 | TYPE 1 |
| `sensorControlMode` | bool | `1` / `0` | TYPE 1 |
| `adaptiveMode` | bool | `1` / `0` | TYPE 1 |
| `lowTemp` | float | -40..85 | TYPE 1 |
| `highTemp` | float | -40..85 | TYPE 1 |
| `lowHum` | float | 0..100 | TYPE 1 |
| `highHum` | float | 0..100 | TYPE 1 |
| `maxOnTime` | uint32_t | 0-86400 | TYPE 1, 3 |
| `delaySec` | int | 0-86400 | TYPE 1, 3 |
| `bootState` | bool | `1` / `0` | TYPE 1, 3 |

**Отличие от MQTT:** через Web доступны **все** параметры, включая WiFi и MQTT-настройки.

## 7. Страницы

### 7.1. Страница состояния (`/`)

**Отображает:**
- Показания датчика (температура, влажность) с цветовой индикацией
- Состояние актуатора (ON/OFF)
- Текущий режим (SENSOR / TIMER / MANUAL)
- Скорость вентилятора (TYPE 1) с графической шкалой
- Статус MQTT, RSSI
- Оставшееся время таймеров (delay, maxOnTime)

**Автообновление:** интервал равен `sensorInterval` (или 5 сек по умолчанию).

**Пример (TYPE 1):**

### 7.2. Страница конфигурации (`/config`)

**Содержит форму со всеми настраиваемыми параметрами:**

- WiFi: SSID, пароль
- MQTT: брокер, порт, пользователь, пароль, Client ID
- Датчик: интервал опроса (TYPE 1,2)
- Пороги: температура, влажность (TYPE 1)
- Управление: задержка включения, аварийное отключение (TYPE 1,3)
- Режимы: скорость, адаптивный режим, состояние при старте, сенсорный режим (TYPE 1)

**Особенности:**
- Пароли отображаются как `(hidden)` и не передаются в форме (оставляются как есть)
- Требуется подтверждение (`confirmSave`) для предотвращения случайного сохранения
- После сохранения — автоматическая перезагрузка

## 8. Режимы работы Web

| Режим | Условие | Поведение |
|-------|---------|-----------|
| **Настройка (AP)** | `PROVISIONING_METHOD == 2 или 3` и нет WiFi | Страница `/` — только ввод WiFi SSID/пароля |
| **Нормальный** | WiFi подключён | Полный функционал: состояние + настройки |

### 8.1. AP-режим (провизионинг)

При включении без сохранённой конфигурации устройство:

1. Создаёт точку доступа с SSID `{prefix}_XXXX`
2. Запускает веб-сервер на `192.168.4.1`
3. Показывает страницу `/` с формой ввода WiFi SSID и пароля
4. После сохранения — перезагрузка и подключение к WiFi

## 9. Обработчики

### 9.1. `web_init(setupMode)`

Инициализирует веб-сервер и регистрирует маршруты.

| Параметр | Значение | Поведение |
|----------|----------|-----------|
| `setupMode = true` | AP-режим | Только страница `/` с формой WiFi |
| `setupMode = false` | Нормальный режим | Полный функционал |

### 9.2. `web_update()`

Вызывается в `loop()` для обработки HTTP-запросов:

```cpp
void web_update() {
    server.handleClient();
}
```

### 9.3. `web_saveConfig()`

Обработчик POST-запроса на `/save`:

1. Копирует текущую конфигурацию как базу
2. Парсит все параметры из формы
3. Валидирует каждый параметр (диапазоны, длины строк)
4. При ошибке — показывает страницу с сообщением
5. При успехе — устанавливает `g_webConfigPending = true`

## 10. OTA-интеграция

**Web не знает о `FEATURE_OTA_ENABLED`.** Доступность OTA определяется вызовом `ota_is_available()`:

```cpp
// html_templates.h
if (ota_is_available()) {
    send(F("<a href='/update' class='link-btn'>Upgrade firmware (OTA)</a>"), context);
}
```

**Маршрут `/update`** регистрируется OTA-слоем через `ElegantOTA.begin(server)`. Это исключение из-за использования библиотеки.

## 11. Требования к доработке

| Проблема | Статус | Решение |
|----------|--------|---------|
| **Web вызывает `ESP.restart()`** | 🔴 Критично | Заменить на `restart_request()` |
| **Web вызывает `g_configManager.set...()`** | 🔴 Критично | Использовать `DeviceController` |
| **Web читает `sensor_*()` напрямую** | 🟡 Средняя | Читать через `IWebStatusProvider` |
| **Web читает `g_configManager` напрямую** | 🟡 Средняя | Читать через `IWebStatusProvider` |
| **`handleToggle()` — заглушка** | 🟡 Средняя | Реализовать через `DeviceController` |
| **`web_handleApProvisioning()` не в том слое** | 🟡 Средняя | Перенести в `provisioning` |
| **OTA-кнопка** | ✅ Исправлено | Использует `ota_is_available()` |
