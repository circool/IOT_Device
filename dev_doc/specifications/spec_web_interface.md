## Web-слой: принципы построения

### Назначение

Web-слой предоставляет HTTP-интерфейс для:
- Отображения состояния устройства (страница `/`)
- Изменения параметров (страница `/config`, форма)
- Точечного управления через GET-запросы (`/set`)
- Обновления прошивки (OTA)

### Режимы работы

| Режим | Условие | Страница `/` | Страница `/config` |
|-------|---------|--------------|-------------------|
| **Обычный** | Есть MQTT и параметры | Страница состояния | Страница изменения параметров |
| **Настройки** | Нет MQTT или нет параметров | Страница ввода всех параметров | Недоступна (редирект на `/`) |

### Рендеринг

- Страница состояния собирается из независимых типовых блоков (`renderField`).
- Каждый блок отвечает за отображение одного элемента:
  - Карточка температуры (с цветовой индикацией)
  - Карточка влажности (с цветовой индикацией)
  - Состояние актуатора (карточка-ссылка)
  - Шкала скорости
  - Режим работы
  - Информационная панель
- Это обеспечивает единообразие стилей и минимизирует дублирование кода.
- Все блоки используют данные из `IWebStatusProvider`.

### Управление состоянием

- Изменения, требующие немедленной реакции (`state`, `sensorControlMode`, `speed`), выполняются через GET-запросы с параметрами (`/set?param=value`).
- Изменения, требующие сохранения в EEPROM и перезагрузки (пороги, таймеры, режимы), выполняются через POST-форму на `/save`.

### Интеграция с другими слоями

- Web-слой **не знает** о `ConfigManager`, `FanActuator`, `Sensor` и т.д.
- Вся бизнес-логика и данные предоставляются через **интерфейс провайдера** (`IWebStatusProvider`), который реализуется в `main.cpp` (оркестратор).
- Web-слой вызывает только методы этого провайдера для получения данных и выполняет редиректы, не вмешиваясь в логику устройства.

### Маршруты

| URL | Метод | Назначение |
|-----|-------|------------|
| `/` | GET | Главная страница (состояние или настройки) |
| `/config` | GET | Страница изменения параметров |
| `/save` | POST | Сохранение параметров из формы |
| `/set` | GET | Точечное изменение параметра (`/set?param=value`) |
| `/update` | GET | OTA-обновление |
| `/resetall` | GET | Сброс всех настроек |

### Параметры `/set`

| Параметр | Тип | Назначение |
|----------|-----|------------|
| `state` | `on`/`off` | Включить/выключить актуатор |
| `sensorControlMode` | `1`/`0` | Включить/выключить сенсорный режим |
| `adaptiveMode` | `1`/`0` | Включить/выключить адаптивный режим |
| `speed` | `0...100` | Установить скорость ШИМ |
| `lowTemp`, `highTemp` | `-40...85` | Установить пороги температуры |
| `lowHum`, `highHum` | `0...100` | Установить пороги влажности |
| `maxOnTime` | `0...86400` | Установить таймер аварийного отключения |
| `delaySec` | `0...86400` | Установить задержку отложенного включения |
| `bootState` | `1`/`0` | Установить состояние при старте |

### Принципы

1. **Единый источник данных** — все данные для отображения берутся из `IWebStatusProvider`.
2. **Минимальная бизнес-логика** — Web-слой не принимает решений, только отображает и перенаправляет.
3. **Чистый HTTP** — все действия выполняются через стандартные GET/POST-запросы.
4. **Стилизация** — единые CSS-классы для всех элементов.
5. **Асинхронное сохранение** — Web не сохраняет в EEPROM напрямую. Только заполняет буфер и устанавливает флаг для оркестратора.
