Zigbee — протокол для построения ячеистых сетей с низким энергопотреблением. Устройство подключается к координатору сети (например, Zigbee-шлюзу) и представляет себя как одно или несколько логических устройств (endpoints) со стандартизированными кластерами.

**Принцип адресации**

Устройство идентифицируется в сети по 16-битному сетевому адресу и 64-битному MAC-адресу. Взаимодействие строится по модели:
`{endpoint} → {cluster} → {attribute}`

**Конечные точки (Endpoints)**

Устройство представляет три конечные точки в зависимости от конфигурации типа:

| Endpoint | Назначение | Применимость |
|----------|------------|--------------|
| 1 | Управление вентилятором | Типы 1, 3 |
| 2 | Датчик температуры и влажности | Типы 1, 2 |
| 3 | Конфигурация устройства | Все типы |

**Кластеры и атрибуты**

*Endpoint 1 — Управление вентилятором (типы 1, 3):*

| Кластер | Тип | Атрибуты |
|---------|-----|----------|
| On/Off (0x0006) | Сервер | `OnOff` — состояние исполнительного механизма |
| Level Control (0x0008) | Сервер | `CurrentLevel` — скважность ШИМ (0–100%) |
| Fan Control (0x0202) | Сервер | `FanMode` — режим работы (ручной/сенсор); `FanModeSequence` — адаптивный режим |

*Endpoint 2 — Датчик (типы 1, 2):*

| Кластер | Тип | Атрибуты |
|---------|-----|----------|
| Temperature Measurement (0x0402) | Сервер | `MeasuredValue` — текущая температура |
| Relative Humidity Measurement (0x0405) | Сервер | `MeasuredValue` — текущая влажность |

*Endpoint 3 — Конфигурация (все типы):*

| Кластер | Тип | Атрибуты |
|---------|-----|----------|
| Basic (0x0000) | Сервер | `ManufacturerName`, `ModelIdentifier`, `SWBuildID` — информация об устройстве и версии прошивки |
| OTA Upgrade (0x0019) | Клиент | Обновление прошивки по воздуху |
| Custom (0xFC00) | Сервер | Пороги датчика (`LowTemp`, `HighTemp`, `LowHum`, `HighHum`); таймеры (`DelaySeconds`, `MaxOnTime`); причина перезагрузки |

**Типы взаимодействия**

| Кластер | Публикация | Управление |
|---------|-----------|------------|
| On/Off | Да. Состояние сообщается через `Report Attributes` | Да. Команды `On`, `Off`, `Toggle` |
| Level Control | Да. Текущий уровень | Да. Команда `MoveToLevel` |
| Fan Control | Да. Текущий режим | Да. Команда `Write Attributes` |
| Temperature Measurement | Да. Периодические отчёты | Нет |
| Relative Humidity Measurement | Да. Периодические отчёты | Нет |
| Basic | Да. Статические атрибуты | Нет |
| OTA Upgrade | Нет | Да. Приём обновлений |
| Custom | Да. Текущие значения | Да. `Write Attributes` для порогов и таймеров |

**Особенности:**
- Обмен данными происходит через механизм биндингов (прямые связи между устройствами) или через координатор.
- Периодичность отчётов датчиков настраивается через конфигурацию кластеров.
- При потере и восстановлении связи устройство автоматически перерегистрируется в сети.
